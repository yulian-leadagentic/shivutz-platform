# screens-export

Two-deliverable audit tool for the TagidAI frontend:

- **(A) Screens gallery** — full-page PNG of every route in
  `services/frontend/src/app/**/page.tsx`, captured at desktop (1440×900)
  and mobile (390×844), RTL + `he-IL`. Emitted as
  `screens-export/index.html` (contact sheet) plus per-shot PNGs.
- **(B) Messages & errors map** — every user-facing string catalogued
  from the frontend (`i18n/he.ts` + JSX Hebrew literals), backend error
  responses (FastAPI + Express `HTTPException` / `res.status(...).json`),
  and notification-template migrations. Emitted as
  `screens-export/messages-map.md` + `messages-map.csv`.

Everything the tool produces lands under `screens-export/` at the repo
root, which is gitignored.

## Prerequisites

- Node 18+
- Auth on staging works via phone `0525278625` + `MASTER_OTP=999999`
  (this is currently wired in pivot-staging).

## One-time setup

```bash
cd tools/screens-export
npm install
npx playwright install chromium
```

## Run the whole pipeline

```bash
npm run all
```

That runs, in order:

1. `enumerate` — walks `services/frontend/src/app/**/page.tsx`, emits
   `routes.json` with `{ path, category, dynamic, auth, register }`.
2. `scan` — catalogues messages into
   `../../screens-export/messages-map.md` + `.csv`.
3. `capture` — Playwright test spec logs in once (per contractor +
   corporation + admin, if the phone has multiple memberships), saves
   `storageState.<role>.json`, then screenshots every route in `routes.json`
   at both viewports. Register-wizard pages capture each step BUT never
   click the final create button — no junk data lands on staging.
4. `gallery` — writes `../../screens-export/index.html` — thumbnails
   grouped Public / Contractor / Corporation / Admin, desktop and mobile
   side-by-side.

## Individual scripts

Each step is independent and idempotent:

```bash
npm run enumerate     # routes.json only
npm run scan          # messages-map.md + .csv only (no Playwright needed)
npm run capture       # screens-export/<viewport>/<slug>.png only
npm run gallery       # index.html from whatever PNGs exist
```

## Overrides

Environment variables read by `screens.spec.ts`:

| var | default | purpose |
|---|---|---|
| `BASE_URL` | `https://frontend-pivot-staging.up.railway.app` | Target |
| `LOGIN_PHONE` | `0525278625` | Test account phone |
| `MASTER_OTP` | `999999` | Master OTP (staging bypass) |

Example: capture against a local Docker stack:

```bash
BASE_URL=http://localhost:3008 npm run capture
```

## Guardrails

- **Staging only** by default. Set `BASE_URL` explicitly to point elsewhere.
- **Read-only.** Register wizards capture each step BUT stop before
  the final submit — no test-org rows created on staging.
- **Baseline tag before any run:** `git tag pre-screens-export` (already
  set by the session that scaffolded this tool).
- **Output is gitignored** — `screens-export/` is not committed.

## Layout

```
  enumerate-routes.mjs    App-Router path resolver → routes.json

  scan-messages.mjs       frontend + backend + template catalogue
  gallery.mjs             contact-sheet HTML generator
  routes.json             (generated by enumerate)
  storageState.*.json     (generated by capture, per role)
  README.md
../..

  desktop/                <slug>.png shots
  mobile/                 <slug>.png shots
  messages-map.md         catalog
  messages-map.csv        catalog CSV
  index.html              contact sheet
```
