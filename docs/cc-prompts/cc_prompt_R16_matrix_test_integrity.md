# §1 · 🔴 `_matrix_skipped_any()` אינו קיים

`scripts/smoke_test.py:2168` מצהיר:

> *"the matrix suite exits non-zero if ANY row was skipped, so CI can't quietly pass on a half-covered matrix"*

`:2271` מפנה אליו בשם:

> *"and `_matrix_skipped_any()` lets us fail loud in `exit_code()`"*

**בדקתי. `grep -rn "_matrix_skipped_any" scripts/` מחזיר שורה אחת — את ההערה עצמה. אין `def`.**

**ו-`exit_code():236`:**

```python
def exit_code(self) -> int:
    return 0 if all(r.ok for r in self.rows) else 1
```

**וכל שורת SKIP נרשמת עם `ok=True`** — `:2300` · `:2366` · `:2424` · `:2451`.

> 🔴 **התוצאה ההפוכה בדיוק מהמובטח:** סביבה בלי `SERVICE_PROVIDER_PHONE`, בלי `ADMIN_PHONE` או בלי מודעת עובדים זרה — **מדלגת על השורות הקריטיות ויוצאת `0`. ירוק. שקט.**

## ⚠️ וזו הפעם השנייה היום

**`search.py:195` טען שקיים נתיב חשיפה ב-`/api/marketplace`. הוא לא נבנה מעולם — וזה מה שאפשר לדליפת ה-P0 לשרוד שלושה סבבי ביקורת.**
**`smoke_test.py:2168` טוען שקיים שער SKIP. הוא לא נבנה מעולם.**

🔴 **הערה שמתארת שער שלא נבנה היא גרועה מאין הערה בכלל — היא גורמת לביקורת הבאה לדלג על הבדיקה.**
**בשני המקרים הכוונה נכתבה ולא יושמה. אל תכתוב הערה בלשון הווה על משהו שאתה מתכנן.**

## Do

- **ממש `_matrix_skipped_any()` באמת**, או הסר את שתי ההערות. **אל תשאיר אותן לא נכונות**
- 🔴 **ההמלצה שלי — לממש.** שורת SKIP תקבל `skipped=True` נפרד מ-`ok`, ו-`exit_code()` יחזיר **`2`** כשיש SKIP במטריצה (`0` = עבר · `1` = נכשל · `2` = לא כוסה). **שלושה מצבים, לא שניים**
- **הפלט יסכם בשורה אחת:** `matrix: 16 passed · 0 failed · 2 skipped (SERVICE_PROVIDER_PHONE)`
- ⚠️ **SKIP מחוץ לסוויטת המטריצה נשאר כפי שהוא.** `:1125`, `:1143`, `:1160` הן בדיקות S1/S2 ולא נגענו בהן

# §2 · 🔴 בדיקת אי-המנייה שולחת קוד אנגלי לחיפוש עברי

`:2380` — הפרובה עצמה:

```python
sc, body, det = _search(api, sess, prof)
```

**ו-`prof` מגיע ישירות מ-`ads.profession_code` (`_foreign_worker_sample:2237`).**

**`profession_code` הוא ה-enum באנגלית.** `001_initial_schema.sql:219`:

```sql
('flooring', 'ריצוף', 'Flooring', 'construction', 1)
```

**כלומר השאילתה שנשלחת היא המחרוזת `flooring`** — לא `ריצוף`, לא `רצפים`.

**וההערה ב-`:2231` טוענת את ההפך:**

> *"the caller queries with `profession_code`'s canonical Hebrew name"*

**אין בקוד שום `JOIN` ל-`professions.name_he`.**

> 🔴 **זו בדיוק המשפחה של הבאג ש-Yulian דיווח עליו — ״flooring במקום רצפים״.**
> **הפעם הוא לא בממשק. הוא בתוך הבדיקה שאמורה להגן על המוצר.**

## Do

- **`_foreign_worker_sample` יחזיר גם `name_he`** — `JOIN professions p ON p.code = a.profession_code`
- **הפרובה תשתמש ב-`name_he`.** ⚠️ **ואם ה-JOIN לא מוצא שורה — זו שגיאה, לא SKIP שקט**
- **תקן את ההערה ב-`:2231`**

# §3 · 🔴 הממצא העיקרי — לפרובה אין בקרת חיוב

**`:2370-2378` מוציא במכוון את הקבלן המאושר ואת האדמין מ-`probe_targets`:**

```python
# Approved contractor + admin see the full catalogue by design

# it's the matrix.
```

🔴 **הנימוק נכון לגבי כיסוי — ושגוי לגבי תוקף.**

**הפרובה טוענת: ״המזהה `ad_id` אינו בתשובה של התאגיד.״**
**אבל היא לא טוענת בשום מקום שהמזהה הזה *כן* חוזר למישהו באותה שאילתה בדיוק.**

## מה זה אומר בפועל

**אם השאילתה לא מחזירה את המודעה לאף אחד** — כי `flooring` באנגלית לא עובר את ה-rewriter (§2), כי ה-rerank הוריד אותה, כי היא לא תואמת —

> **הטענה ״המזהה נעדר״ מתקיימת מעצמה.**
> **הבדיקה ירוקה בין אם `viewer_scope_wheres` עובד ובין אם מחקת אותו לגמרי.**

🔴 **זו לא בדיקה. זו אמירה על שאילתה שלא החזירה כלום.**

**וזה בדיוק מה שכלל 5 ב-R14 §1 נועד לתפוס** — *״בדיקה שלא ראית נופלת אינה בדיקה״*. **ההדגמה הזו לא הופיעה בדוח שלך. אם היית מריץ אותה, היית מגלה את §3 בעצמך: הבדיקה לא הייתה נופלת.**

## Do

- 🔴 **הוסף את הקבלן המאושר לפרובה — כבקרת חיוב, לא ככיסוי.** **אותה שאילתה בדיוק, ו-`ad_id` חייב להיות *כן* בתשובה שלו**
- 🔴 **אם הוא לא רואה אותה — הפרובה פסולה ויוצאת `2`,** עם `PROBE INVALID · foreign ad {id} not returned to approved contractor for query '{name_he}' — the absence assertions below prove nothing`. **לא ״עבר״**
- **סדר: קודם בקרת החיוב. רק אם עברה — ארבע טענות ההיעדר**
- **בחירת המודעה:** אם המודעה הראשונה לא חוזרת לקבלן, **נסה את הבאה** (עד 3). ⚠️ **רק מודעה שהוכח שהיא נראית לקבלן כשירה לשמש כפרובה**
