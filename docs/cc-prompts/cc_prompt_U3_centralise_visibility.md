# §1 · התיקון — פונקציה אחת, לא שומר חמישי

> **אם תוסיף שומר רביעי ל-`/public/{id}` וחמישי ל-`/recent`, יופיע שישי בשבוע הבא.**
> **הכלל חייב לחיות במקום אחד שכל מסלול קריאה קורא לו.**

## 1.1 · שני עוזרים משותפים

```
viewer_scope_wheres(x_entity_id, x_entity_type) -> (wheres, params)
    תאגיד  →  ["(a.ad_type <> 'worker' OR a.owner_entity_id = %s)"], [id]
    קבלן · אדמין · אנונימי  →  ([], [])

require_contractor_approved(x_entity_id, x_entity_type) -> None | raise 403
    קבלן שאינו 'approved'  →  403 entity_not_approved
    כל השאר  →  עובר
```

**שים אותם ב-`app/services/` ליד `subscription_limits.py`** — לא בתוך `routes/`. **שני ראוטרים שונים חייבים לייבא את אותו קוד.**

## 1.2 · החיבור

| נתיב | מה להוסיף |
|---|---|
| `POST /search` | **`require_contractor_approved`** — ממצא 4. הסינון כבר שם |
| `GET /ads/public/{id}` | שניהם |
| `GET /ads/public/recent` | שניהם + לקבל את ה-headers |
| `GET /ads/public/featured` | שניהם + לקבל את ה-headers |
| מעבר near-match | **אמת שהוא יורש. אם לא — חבר** |

⚠️ **`recent` ו-`featured` לא מקבלים היום headers בכלל.** צריך להוסיף להם `Header(default=None)` — **וודא שהגייטוויי מעביר אותם.** הוא מעביר (`index.js:279-283` מזריק גם בנתיב ציבורי כשיש טוקן), אבל **אמת בפועל** — זה בדיוק סוג הפער של ה-404.

## 1.3 · מה `pending` רואה בחיפוש

L2 §1 קבע: **ספירות בלבד, בלי תוכן.**

**בדוק מה הפרונט מצפה לו היום.** אם הוא לא בנוי לתשובה מקוצרת — **403 עם `entity_not_approved` ומסך "בבדיקה" עדיף על מסך ריק.** **דווח מה בחרת ולמה.**

## 1.4 · אל תשבור את מה שעובד

- **קבלן מאושר — ללא שינוי בכל חמשת המסלולים**
- **אדמין — עובר בכל מקום**
- **דיור — תאגיד ממשיך לראות הכל.** הסינון על `ad_type = 'worker'` בלבד
- **אנונימי — נשאר חסום** ב-3/4/5

# §3 · לסגור את פער הכיסוי ב-S2

**S2 לא בדק את `/recent` ו-`/featured`. לכן ממצא 5 שרד.**

**הוסף ל-`--suite core`:**

- תאגיד → `/ads/public/recent` → **רק מודעות עובדים שלו**. השווה `owner_entity_id`
- תאגיד → `/ads/public/featured` → אותו דבר
- תאגיד → `/ads/public/recent?ad_type=housing` → **רואה גם של אחרים**
- קבלן `pending` → `/search` → **403 או ספירות בלבד**, לפי §1.3
- אנונימי → שלושתם → **401**
- **near-match:** תאגיד בשאילתה שמפעילה מעבר שני → **אפס מודעות זרות**

🔴 **אלה נוספות ל-`core`, לא ל-`money`.** הן בדיקות נראות ורצות בכל הרצה.

# §4 · מה שנשאר ל-Yulian

**`INTERNAL_BATCH_SECRET` לא מוגדר בסטייג'ינג** → `renewal-batch` מחזיר 401 לכולם → **החידוש החודשי לא רץ מעולם.**

**זו הגדרה, לא באג.** אבל המשמעות חשובה: **אף אחד לא הוכיח שהחידוש עובד מקצה לקצה.**

**אחרי שיוגדר — הרץ מחדש `--suite money` ודווח.** עד אז §2.2 של S2 בודק נתיב שמחזיר 401 ולא את הלוגיקה.
