# §2 · מה משתנה בפועל — שלושה דברים, לא הסרה גורפת

## 2a · `viewer_scope_wheres` — החוזה החדש

`services/user-org/app/services/visibility.py`

```
anonymous          →  (["1=0"], [])
contractor מאושר   →  ([], [])
corporation        →  (["(a.ad_type <> 'worker' OR a.owner_entity_id = %s)"], [id])   ← ללא שינוי
service_provider   →  (["a.ad_type <> 'worker'"], [])                                  ← השתנה מ-1=0
admin              →  ([], [])
```

**שני שינויים בלבד:**
- **`service_provider`: מ-`1=0` ל-`a.ad_type <> 'worker'`.** 🔴 **זה הבאג שראה Yulian** — `1=0` חסם לו גם דיור וגם שירותים
- **`anonymous`: מ-`([], [])` ל-`1=0`** — כי עד היום הוא נחסם בגייטוויי ולא הגיע לכאן בכלל. **עכשיו הוא מגיע, וצריך לחסום אותו כאן**

🔴 **`corporation` לא משתנה. אל תיגע בו.**

## 2b · `_search_marketplace` — לא מקבל scope, וזה נכון

`search.py:215` כבר לא מקבל scope, ולכן שירותים נלווים חוזרים לכולם. **זו בדיוק ההתנהגות הרצויה. אל תשנה.**

## 2c · הגייטוויי — `/api/search` נפתח

`services/gateway/src/index.js` — **הוסף `/api/search` ל-`PUBLIC_PREFIXES`.**

🔴 **ורק אותו.** `/api/ads/{id}`, `/api/reveals` וכל השאר נשארים סגורים.
⚠️ **ודא שהגייטוויי ממשיך להעביר את כותרות הזהות גם במסלול ציבורי** — יש כבר טיפול כזה ב-`:279-283`. **בלי הכותרות, קבלן מחובר ייראה כאנונימי ויקבל שירותים נלווים בלבד.**

## 2d · קבלן `pending`

`search.py:285` — `require_contractor_approved` מחזיר היום **403 על כל הנתיב**.

**עכשיו שהחיפוש פתוח לכולם, 403 גורף אינו עקבי.**

**Do:** **קבלן `pending` מקבל 200 עם שירותים נלווים בלבד** — כמו אנונימי — **ובמקטע העובדים ההודעה הקיימת ״החשבון שלך עדיין בבדיקה״.**

🔴 **אל תסיר את `require_contractor_approved` מנתיבים אחרים.** הוא שומר על החשיפה ועל מסלולים נוספים. **כאן בלבד הוא הופך מ-403 ל-scope.**
