# CC prompt — M4: חיבור הקטגוריות לחיפוש

## 🔴 קרא את זה לפני הכול

**זה השלב שבו הבאג שסגרנו יכול לחזור דרך הדלת האחורית.**

היום `PROFESSION_KEYWORDS`, `ORIGIN_KEYWORDS` ו-`REGION_KEYWORDS` **קשיחים בתוך `query_rewriter.py`**, ורשימת הערכים המותרים כתובה **מילולית ב-system prompt**.

המשמעות: **קטגוריה שאדמין ייצור מחר תהיה בלתי נראית לחיפוש.**
ולא רק בלתי נראית — **מסוכנת.** ערך שאינו ב-whitelist נזרק; אם Haiku תחזיר `"רואי חשבון"` והקטגוריה לא בקבוצה, המנגנון יפיל אותה, והחיפוש יחזיר את כל הקטלוג.

**זה בדיוק S1.** ההבדל היחיד: אז המקור היה LLM שהמציא ערך, וכאן המקור יהיה אדמין שיצר ערך אמיתי שהקוד לא מכיר.

# מה חייב להשתנות

## 1 · קבוצות ה-enum נטענות מה-DB בזמן ריצה
`service_categories` → קבוצת קודים תקפים, **cache 30–60 שניות**. קטגוריה חדשה נכנסת לחיפוש **בלי פריסה**.

> **אם ה-DB לא זמין — ליפול לרשימה הקשיחה, לא לרשימה ריקה.** רשימה ריקה = כל חיפוש מחזיר את כל הקטלוג.

## 2 · ה-system prompt נבנה דינמית
רשימת הקודים המותרים מוזרקת מה-DB. **אסור שתישאר רשימה מילולית שנייה בקוד** — שתי רשימות שמתפצלות הן הבאג הבא.

## 3 · הנרדפות מ-`search_synonyms_he` נכנסות לנפילה-לאחור
זה מה שמחזיק את החיפוש כשה-LLM מחמיץ. **בלעדיהן fake-mode לא ימצא שום קטגוריה.**

## 4 · ממד `vertical`
`worker | housing | service`. **אותו כלל מ-`ed15382`: ערך לא תקף → נסיגה ל-fake, לעולם לא ל-`None`.**

## 5 · הפרדת מסלולים 🔴
שאילתת שירותים **לא מחזירה מודעות עובדים**, ולהפך. **זו הבדיקה שהכי קל להיכשל בה** — שני המסלולים חולקים את `ads` ואת אותו rewriter.

## החדש
- [ ] `"רואה חשבון לקבלנים"` → קטגוריה נכונה, **בלי מודעות עובדים**
- [ ] `"השכרת פיגומים בצפון"` → קטגוריה + אזור
- [ ] `"מתווך לעובדים זרים"` → קטגוריית מתווכים, **לא מודעות עובדים.** זו המלכודת המפורשת
- [ ] **קטגוריה שנוצרה דקה קודם באדמין** → נמצאת בחיפוש **בלי פריסה**
- [ ] **הכול גם ב-`LLM_REWRITER_FAKE_MODE=1`** — שם הנרדפות הן כל מה שיש
- [ ] `"מתכנת פייתון"` → `None`. **לא ניחוש, לא קטגוריה אקראית**
