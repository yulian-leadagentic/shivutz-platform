# §1 · 🔴 רשימת הקטגוריות חוזרת ריקה — אף אחד לא יכול להירשם כספק

**Yulian, 22.09:** *״לא מצליח להירשם.״* **הצילום מראה את ״קטגוריית השירות *״ פתוח עם רשימה אפורה ריקה.** השדה חובה, ולכן ההרשמה מתה שם.

## השורש

`services/user-org/app/routes/marketplace.py:285`

```python
@router.get("/categories")
def list_public_categories():
    cur.execute(
        """SELECT code, name_he, name_en, icon_slug, sort_order
             FROM marketplace_categories
            WHERE is_active = 1
            ORDER BY sort_order, code"""
    )
    return [_serialize(r) for r in cur.fetchall()]
```

**ו-`_serialize` (`:118`) הוא רשימת ההיתר שאני ביקשתי ב-R15 §3a:**

```
_PUBLIC_LISTING_FIELDS = id · category · subcategory · title · description ·
                         city · region · price · price_unit · capacity ·
                         is_furnished · available_from · images_json ·
                         status · created_at · updated_at · advertiser_entity_type
```

> 🔴 **אף אחד מחמשת השדות שהשאילתה שולפת — `code`, `name_he`, `name_en`, `icon_slug`, `sort_order` — אינו ברשימה.**
> **`_serialize` מסנן את כולם. הנתיב מחזיר `[{}, {}, {}, …]` — מספר נכון של אובייקטים ריקים.**
> **ולכן ה-`<select>` מרנדר שורות ריקות: בדיוק הרשימה האפורה הריקה בצילום.**

## ⚠️ וזו הטעות שלי

**R15 §3a הפך את `_serialize` לרשימת היתר — וזה היה נכון, הוא סגר דליפת P0 של טלפונים.**
**אבל `list_public_categories` חולק את אותה פונקציה, וההקרנה שלו שונה לגמרי.**

🔴 **ובדיקות הקבלה של R15 בדקו `GET ""` ו-`GET /{id}` בלבד.** **אני עצמי מניתי את `/categories` באותו סבב כשהוכחתי שאין נתיב חשיפה בקובץ — ואז כתבתי קבלה שלא נוגעת בו.**

**מאז R15 הרשמת ספק בלתי אפשרית.**

## Do

- 🔴 **`list_public_categories` לא ישתמש ב-`_serialize` של המודעות.** **סריאלייזר משלו עם רשימת היתר משלו:** `code` · `name_he` · `name_en` · `icon_slug` · `sort_order`
