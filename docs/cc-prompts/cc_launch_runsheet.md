## ⭐ STANDING RULES — חלים על כל פריט

1. `git tag pre-<id>` **לפני** כל פריט.
2. **ענף: `pivot/v2`.** הרץ `git rev-parse --abbrev-ref HEAD` ואמת בעצמך. **אל תסמוך על `CLAUDE.md`** — הוא עדיין אומר `staging` וזה לא נכון. **`main` (production) — רק באישור מפורש של Yulian.**
3. **אין `git add -A`.** CRLF הופך את `git status` ללא-אמין. stage לפי שם קובץ.
4. **390 קודם, ואז דסקטופ.** RTL, טוקנים של ה-DS.
5. **DoD = root cause + צילומי לפני/אחרי + ה-SHA שנפרס.** `npm run build` לבדו לא מספיק.
6. **עצור ודווח** אם התיקון נכנס לתוך לוגיקה שלא נכללת בפרומט.

## הסדר — ומה חוסם את מה

```
L1  חורי הרשאה            SEC-1 + SEC-2    ← ראשון. חשיפת מידע אישי.
L2  מודל הנראות           SEC-3 + SEC-4    ← אחרי L1
L3  חיווי אמון             SEC-5 + PRD-3    ← אחרי L2 (משתמש ב-serializer שלו)
──────────────────────────────────────────
L4  תמחור ומושבים          PAY-2            ← חוסם את L5
L5  גבייה אמיתית           PAY-1 + PAY-3    ← הפריט הארוך ביותר
──────────────────────────────────────────
L6  דפים משפטיים           LEG-1 + LEG-2    ← עצמאי, אפשר במקביל
L7  רשומות חשיפה           PRD-1 + PRD-2
L8  ניטור ותשתית           OPS-1 + OPS-2 + OPS-3
```

**L1 ראשון בלי דיון.** חמישה נתיבים מגישים היום מספרי טלפון ומסמכים לכל מי שמחזיק טוקן.

**L4 לפני L5.** אי אפשר לבדוק גבייה מקצה לקצה כשמחיר המנוי הוא `NULL`.

**L6 ו-L8 עצמאיים** — אם יש חלון קצר לפני חג, הם המועמדים.
