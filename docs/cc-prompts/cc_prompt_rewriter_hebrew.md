## Root cause — אותר, אל תחפש מחדש

**שלוש חוליות שמצטרפות לכשל אחד.**

### 1. Haiku מחזיר מחרוזות תצוגה בעברית, לא קודים
עבור `"רתך"` הוא מחזיר `"רתכים"` ולא `scaffolding`. עבור `"סין"` — `"סין"` ולא `CN`. ה-system prompt ב-`query_rewriter.py` אמנם מונה את הקודים, אבל המודל מהדהד את שפת הקלט.

### 2. ה-merge דורס את התשובה הנכונה של fake
```python
merged = {**fake, **{k: v for k, v in parsed.items() if v is not None}}
```
`rewrite_fake` כבר חילץ `scaffolding` נכון מטבלת `PROFESSION_KEYWORDS`. הערך העברי של ה-LLM **אינו None**, ולכן הוא **דורס** אותו.

### 3. ה-guard של S1 מאפס במקום לסגת
`_validate_enums` מזהה נכון ש-`"רתכים"` אינו enum תקף → מציב `None`. אבל בשלב הזה `scaffolding` של fake **כבר נמחק ע"י ה-merge**. התוצאה: `null`.

> **⚠️ זו טעות בספסיפיקציה של S1, לא באיכות המימוש.** הפרומט המקורי אמר במפורש *"הפל ל-None — לא לערך של fake, fake כבר במקום מה-merge"*. ההנחה הזאת שגויה: fake **לא** במקום, הוא נדרס. המימוש נכון ביחס למה שנתבקש.

**התוצאה נטו: `mode=real` נותן תוצאות גרועות יותר מ-`mode=fake`.** אנחנו משלמים על Haiku כדי לאבד תשובה שהייתה נכונה בחינם.

### הבאג התאום — S3 לא מכסה את נתיב ה-LLM
`_quantity` תוקן ב-S3 כך שיקבל מספר רק ליד מילת-כמות. **אבל הוא רץ רק ב-fake.** ב-real, Haiku מחזיר `quantity=3` מתוך `"3 חודשים"`, וה-guard רק בודק טווח 1–9999 → 3 עובר. `"פועלים ל-3 חודשים"` נכשל בדיוק כמו לפני S3.

## ⭐ STANDING RULE
`git tag pre-rw` לפני. staging בלבד. DoD = סוללה מלאה עם `mode=real` **וגם** `mode=fake`, זו לצד זו.

## Do

### 1. נסיגה ל-fake במקום איפוס 🔴 **התיקון המרכזי**

ב-`_validate_enums` — כשערך מה-LLM אינו enum תקף, **סוג לערך של `fake`, לא ל-`None`**:

```
value = llm_value  אם תקף
        אחרת fake_value  אם תקף
        אחרת None
```

זה דורש שהפונקציה תראה את `fake` — העבר אותו כפרמטר. **הכלל: ה-LLM יכול רק לשפר, לעולם לא להרע.**

רשום את ההחלטה:
`print(f"[qrewrite] enum_fallback field={k} llm={v!r} → fake={fake_v!r}")`

### 2. `ad_type` — אותו כלל
היום ערך לא תקף **מקבע ל-`"worker"`**. זה מה שהופך `"דיור למרכז"` לחיפוש עובדים. **סוג ל-`fake["ad_type"]`** — `rewrite_fake` כבר מזהה `HOUSING_KEYWORDS` ("דיור", "לינה", "מגורים") נכון.

### 3. `quantity` — להחיל את S3 גם על נתיב ה-LLM
היום רק חסם טווח. **אמת את הכמות של ה-LLM מול אותה לוגיקה של `_quantity`:** אם המספר בשאילתה אינו צמוד למילת-כמות — הפל אותו. אל תשכפל את הקוד; קרא לאותה פונקציה.

### 4. ללמד את Haiku להחזיר קודים
תקן את ה-system prompt כך שיחזיר **קודים באנגלית בלבד**, עם **דוגמאות עברית→קוד** מפורשות:
```
רתך / רתכים → scaffolding
פועלים → general
סינים → CN
מרכז → center
דיור / לינה → ad_type=housing
```
הדגש: *"Return ONLY the English codes listed. Never return Hebrew display names."*

**זה שיפור, לא הגנה.** סעיפים 1–3 חייבים להחזיק גם אם ה-LLM ממשיך להחזיר עברית.

### 5. להוסיף טסטים שתופסים בדיוק את זה
- LLM מחזיר `{"profession_code": "רתכים"}` על `"רתך"` → התוצאה **`scaffolding`**, לא `None`
- LLM מחזיר `{"ad_type": "מגורים"}` על `"דיור למרכז"` → התוצאה **`housing`**, לא `worker`
- LLM מחזיר `{"quantity": 3}` על `"פועלים ל-3 חודשים"` → התוצאה **`None`**
- LLM מחזיר קודים תקפים → עוברים כמו שהם (בלי רגרסיה על S1)

# נספח · שני פריטים שנחשפו ולא בסקופ

**A · באג ה-BN ב-seeder.** `israeliIdWithChecksum` ב-`catalog.mjs` מכווץ BN 591000000-005 ל-005 ו-006-009 ל-013. רק **2 תאגידים** נוצרים במקום 10, ולכן `housing` קיבל 2 שורות בלבד. עקפו זאת ב-backfill ישיר ב-SQL (`1cfbe91`) — **ה-seeder עצמו עדיין שבור**. סבב נפרד.

**B · אי-דטרמיניזם בין הרצות.** `"פועלים ל-3 חודשים"` החזיר `plastering` בהרצה אחת ו-`flooring` באחרת. לא בעיית אבטחה — אבל אחרי תיקון 1–4 שווה לבדוק אם זה נעלם. אם לא, ה-cache ב-Redis לא תופס כמו שצריך.
