# §1 · 🔴 P0 — כל 401 זורק את הגולש ל-`/login`, גם אם מעולם לא היה מחובר

## מה מצאתי

`services/frontend/src/lib/api/client.ts:285-304`

```js
if (res.status === 401 && typeof window !== 'undefined') {
  const newToken = await tryRefresh();     // אין refresh token → null
  if (newToken) { /* retry */ }
  window.location.href = '/login';         // ← ללא תנאי
  throw new ApiError('Unauthorized', …);
}
```

**כל 401, מכל endpoint, מעביר את הדפדפן ל-`/login`.**

## למה זה נשבר עכשיו ולא לפני

**L2 הפך נתיבים שהיו ציבוריים ל-401:** `/api/search`, `/api/ads/public/recent`, `/featured`, `/{id}`.

> **`client.ts` לא נגע מאז.** התאריך על הקובץ מקדים את כל עבודת ההשקה.
> **L2 יצר את ה-401-ים. אף אחד לא לימד את הלקוח ש-401 הוא עכשיו מצב תקין עבור אנונימי.**

## התוצאה בפועל

```
מבקר אנונימי נכנס ל-/
  → רכיב כלשהו קורא לנתיב שנסגר
  → 401
  → window.location.href = '/login'
  → הוא לא רואה את דף הבית. לעולם.
```

**זה מסביר:**

| ממצא | הסבר |
|---|---|
| **2** — נזרק למסך כניסה ולא חוזר לדף הבית | ישירות |
| **5** — אי אפשר להמשיך את הבדיקה | ישירות |
| **1** — שירותים נלווים "לא פעיל" | `/marketplace` ציבורי, אבל הוא נזרק לפני שהוא רואה אותו |

🔴 **זה אומר שאף מבקר אנונימי לא יכול להשתמש באתר. זה עוצר השקה.**

## Do

### 1.1 · הפנייה רק למי שהייתה לו סשן

```
היה טוקן (או refresh token) ← הסשן פג באמת
    → נסה refresh → נכשל → /login   ✅ ההתנהגות הקיימת נכונה

לא היה טוקן כלל ← מבקר אנונימי
    → אל תפנה. זרוק ApiError והנח לקורא לטפל
```

**האבחנה היא "האם היה כאן סשן", לא "האם השרת אמר 401".**

### 1.2 · מצוא את הקוראים

```bash

       services/frontend/src/components/landing/
```

**דווח כל קריאה שרצה בדף הבית בלי טוקן.** U1 §1b היה אמור לדלג עליהן כשאנונימי — **בדוק אם זה באמת קרה בכל המקומות.**

### 1.3 · הבדיקה שאי אפשר לוותר עליה

**חלון פרטי → `/` → נשאר ב-`/`. הקונסולה נקייה מ-401. לולאת הדמו רצה.**

# §2 · ממצא 4 — "טוען אזורים" נתקע ברישום קבלן

`/api/enums` **הוא ציבורי בגייטוויי**, אז זו לא אותה סיבה כמו §1.

**אבחן קודם:** פתח את הטופס, F12 → Network → **דווח את הקריאה לאזורים: status, גוף, וכמה זמן.**

חשודים:
- שירות `worker` (שמגיש `/api/enums`) לא עונה או קורס
- הקריאה נכשלת **והרכיב נשאר ב-`loading` לנצח** — אין `catch` שמעביר ל-מצב שגיאה

🔴 **בכל מקרה — "טוען…" לנצח הוא באג בפני עצמו.** גם אם ה-API יתוקן: **כשל חייב להציג הודעה וכפתור "נסה שוב", לא ספינר נצחי.** תקן את שניהם.

⚠️ **זה חוסם רישום קבלן — כלומר חוסם את כל משפך הכניסה.** קדימות מיד אחרי §1.

# §3 · ממצאים 6 ו-7 — מסך הקבלן

## 6 · המנוי מציג "קרתה תקלה, נסה שוב"

**אבחן:** איזו קריאה נכשלת ומה ה-status. חשודים: `/payments/subscriptions/me` · שירות `payment` · הקשר ישות.

**ואם הקבלן פשוט בלי מנוי — זו לא תקלה.** ההודעה צריכה להיות *"אין לך מנוי פעיל"* עם כפתור רכישה, **לא שגיאה אדומה.**

## 7 · חסרים שני נתונים שהקבלן צריך

הוסף לדשבורד:

- **`X מתוך 5 משתמשים`** — הנתונים קיימים מ-L4 (`included_users`, `max_users`, `extra_user_price_nis`)
- **רמת האימות של הקבלן** — `verification_tier` / `approval_status` / `kablan_verified_at`
  - מאומת מול פנקס הקבלנים → `✓ קבלן מאומת`
  - ממתין → `בבדיקה` + **מה חסר וכמה זמן צפוי**

> **לקבלן שמשלם אין היום דרך לדעת מה הוא קנה ומה מצבו.** שני הנתונים כבר ב-DB — **זו תצוגה, לא פיתוח.**

## 7b · השם חסר

בצילום כתוב **"שלום"** בלי שם. **אם `full_name` ריק — הצג את שם החברה. לא ברכה קטועה.**
