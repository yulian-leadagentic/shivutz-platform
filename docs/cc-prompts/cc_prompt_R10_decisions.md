# 2 · `extra_user_price_nis` לספק

```
service_provider  →  extra_user_price_nis = 50
contractor        →  80   (ללא שינוי — 071:39,44,50)
```

**₪50, נמוך ממחיר הקבלן.** הנימוק: ספק הוא יישות קטנה יותר בממוצע, ומשרדי תיווך עם 8-10 עובדים הם הביקוש שזיהינו.

✅ **וזה זול לממש בדיוק כי `extra_user_price_nis` הוא כבר עמודה per-plan ב-`subscription_plans` (071:29), לא קבוע בקוד.**

🔴 **ולכן — הבדיקה היחידה שחשובה כאן:** `grep` על מסלול רכישת המושב ומסכי הניהול. **כל מקום שקורא `80` כקבוע במקום מהשורה של התוכנית הוא באג שעכשיו ייחשף.** דווח מה מצאת גם אם לא תיקנת.

**`included_users=5` · `max_users` — ראה §4 להלן.**

# 4 · כתובות בדיקה בסטייג׳ינג

## 🔴 הכלל

```
זרעים ובדיקות  →  @example.com   בלבד
```

**`example.com` שמור ב-RFC 2606. הוא לא ניתן למסירה מעצם הגדרתו** — כלומר הבדיקה לא יכולה להגיע לאף אחד בטעות, גם אם מישהו יטעה בהגדרה.

```
provider-seed@example.com · contractor-seed@example.com · corp-seed@example.com
```

## 🔴 ואיסור מפורש

**אל תשתמש ב-`temp@gmail.com` כיעד בדיקה. בשום מקום.**

**זו אינה כתובת ריקה** — handle בן ארבע אותיות בג׳ימייל תפוס מזמן ע״י אדם אמיתי. **שליחת בדיקות אליה שולחת דואר לזר.** היא מוחלפת ב-§5.

## הצעה — שער יציאה, מסומנת `לאישור Yulian`

**היום שום דבר לא מונע מקוד בסטייג׳ינג לשלוח מייל לכתובת אמיתית.** זרע אחד עם כתובת אמיתית, או `site_settings` שהועתק מפרודקשן, וזה קורה.

**`EMAIL_ALLOWLIST_DOMAINS=example.com,tagidai.com`** — כש-`NODE_ENV !== 'production'`, שירות ההתראות **מסרב** לשלוח לדומיין שאינו ברשימה, ומלוגג את מה שנחסם.

⚠️ **~10 שורות בשכבת השליחה, נקודה אחת.** 🔴 **אל תעצור בגלל זה ואל תפזר תנאים ברחבי הקוד. אם זה לא נקי בנקודה אחת — דווח ואל תעשה.**

# 5 · מייל רכז הנגישות — מחליף את `temp@gmail.com`

```
a11y_coordinator_email  =  accessibility@tagidai.com
a11y_coordinator_phone  =  0525278625        (ללא שינוי)
a11y_coordinator_name   =  יוליאן אברמוביץ׳   (ללא שינוי)
```

🔴 **שער לפני שזה עולה:** **ודא שהתיבה קיימת ומקבלת דואר.** שלח אליה ודווח שהגיעה.

**אם היא לא קיימת — עצור, דווח, והשאר את השדה `NULL`.** לפי R14 §2, שדה ריק → הבלוק לא מרונדר.

> **הצהרה שמפנה לתיבה שלא קיימת אינה טובה מהצהרה בלי כתובת — היא גרועה יותר.** התקנות מחייבות מענה תוך 60 יום, ותלונה לנציבות על פנייה שלא נענתה היא בדיוק מה שזה מייצר.

⚠️ **זה מבטל את `temp@gmail.com` מ-R14 §2 ואת ההערה ב-§2c. השתמש בערך הזה.**

# 6 · נוסח מייל הברוכים-הבאים לספק

**זו טיוטה מלאה. Yulian עורך ב-`/admin/notifications/test` אחרי שתשתול אותה. אל תמתין לו.**

## Subject

```
ברוכים הבאים ל-TagidAI — החשבון שלך פעיל
```

## Body

```
שלום {contact_name},

החשבון של {business_name} ב-TagidAI פעיל.

המסלול שלך: {plan_name} · {category_name}
{promo_block}

מה עכשיו:

1. פרסם את המודעה הראשונה שלך
   {cta_url}

2. המודעה שלך תופיע בחיפוש של קבלנים ותאגידים
   שמחפשים {category_name} — בעברית חופשית, בלי טפסים.

3. פנייה מלקוח תגיע אליך במייל ובמסך הניהול שלך.

צריך עזרה? השב למייל הזה.

TagidAI
```

## `{promo_block}` — מוזרק מ-`site_settings.launch_promo_end`

**כשהתאריך בעתיד:**

```
במסגרת מבצע ההשקה, הפרסום שלך ללא עלות עד {launch_promo_end}.
לא נחייב אותך ללא הודעה מראש.
```

**כשעבר — הבלוק לא מרונדר.** 🔴 **אל תשאיר שורה ריקה ואל תדפיס את התאריך פעמיים.**

## 🔴 חמישה כללים

1. **עברית · RTL · `dir="rtl"`** בגוף ה-HTML
2. 🔴 **`{cta_url}` מוביל ישירות ל-`/provider/marketplace/new` עם הקטגוריה שלו כפרמטר** — **אותה נחיתה בדיוק** שהוא מקבל אחרי ההרשמה. זו הדרישה מהסבב הקודם: *״לאחר הרישום המשתמש צריך לעבור למסך יצירת המודעה שלו״*
3. **בלי מחיר בגוף המייל** מעבר ל-`{plan_name}` — המחיר משתנה מהאדמין והמייל יתיישן
4. **כל השדות מהישות. אפס ערכים קשיחים** — כולל שם המסלול ושם הקטגוריה
5. ⚠️ **שדה ריק → הימנע מ-`{}` בפלט.** בדוק עם ספק בלי `contact_name`
