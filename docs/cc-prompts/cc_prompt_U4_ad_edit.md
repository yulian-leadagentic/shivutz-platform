# §2 · 🔴 באג שקיים בוודאות, גם אם הוא לא זה של היום

```python
cur.execute(sql, params)
if cur.rowcount == 0:
    raise HTTPException(status_code=404, detail="ad_not_found")
```

**pymysql מחזיר ברירת מחדל את מספר השורות ש*השתנו*, לא ש*הותאמו*.**

> **המשמעות: תאגיד שפותח את טופס העריכה ושומר בלי לשנות דבר — או משנה שדה לערך זהה — מקבל `404 המודעה לא נמצאה`.**
> **המודעה שלו. קיימת. והמערכת אומרת לו שהיא לא.**

**Do:** להבחין בין "לא נמצאה" ל"לא השתנתה":

```
1  SELECT id FROM ads WHERE id=%s AND owner_entity_id=%s AND deleted_at IS NULL
2  לא קיים                →  404 ad_not_found
3  קיים + rowcount == 0   →  200 עם השורה הנוכחית   ← אין שינוי, אין שגיאה
4  rowcount > 0           →  200 כרגיל
```

**200 ולא 404** — שמירה בלי שינוי היא פעולה מוצלחת, לא כישלון.

⚠️ **אל תפתור את זה בהוספת `CLIENT.FOUND_ROWS` לחיבור.** זה משנה התנהגות של **כל** שאילתה בשירות, כולל מסלולים שנבדקו השבוע.

# §5 · אחרי התיקון — לכסות את זה בסמוק טסט

**`--suite core`:**

- תאגיד עורך מודעה שלו · **שינוי אמיתי** → **200**, השדה השתנה ב-DB
- תאגיד שומר **בלי שינוי** → **200**, לא 404
- תאגיד עורך מודעה **של תאגיד אחר** → **404**
- קבלן מנסה `PATCH /ads/{id}` → **403**
