# §1 · 🔴 הפרונט מתעלם מ-`primary_section`

**`POST /api/search` עם `{"query":"ביטוח"}` — התשובה המלאה של השרת:**

```json
{
  "total": 0,
  "results": [],
  "marketplace_matches": [
    "ביטוח תאונות עבודה וצד ג׳",
    "הסעות יומיות לאתרי בנייה — מיניבוס 20 מקומות",
    "חבילת ביטוח משולבת לתאגידים",
    "ביטוח רפואי לעובדים זרים — כיסוי מלא"
  ],
  "primary_section": "marketplace"
}
```

**השרת אומר במפורש: אפס מודעות עובדים · ארבעה שירותים · הצג שירותים ראשון.**

**והמסך מציג:**

```
14 תוצאות מודעות · 4 שירותים נלווים
   6 פועלים כלליים מסין · ירושלים
   2 ריצוף מסין · צפון
   …
```

> 🔴 **`results` ריק — אז מאיפה 14?** **מ-`near_matches`.**
> **הפרונט סופר את `near_matches` בתוך ״תוצאות מודעות״, מרנדר אותן בראש, ו-`primary_section` לא משפיע על כלום.**

## Do

- 🔴 **`primary_section` קובע סדר.** `"marketplace"` → **מקטע השירותים הנלווים ראשון.** `"ads"` → מודעות ראשון. **קרא את השדה, אל תסיק אותו**
- 🔴 **`near_matches` אינן תוצאות.** **אל תספור אותן במונה.** כשהמונה אומר ״14 תוצאות״ ו-`total: 0` — **המונה שקרן.** **המונה = `total` + `marketplace_matches.length`, כל אחד בנפרד ומתויג**
- **`near_matches` מרונדרות מתחת, תחת כותרת שמסבירה שהן קירוב** — לא באותה רשימה ולא באותו מונה
- ⚠️ **אם `total === 0` ו-`marketplace_matches.length > 0`** — **אל תציג ״לא נמצאו תוצאות״ בשום צורה.** יש תוצאות, הן פשוט לא מודעות עובדים
- **`grep` על כל מקום בפרונט שקורא `near_matches` — דווח רשימה לפני שינוי**

# §2 · 🔴 `_search_marketplace` — `LIKE` על מחרוזת שלמה, בלי קטגוריה ובלי שורש

`services/user-org/app/routes/search.py:224`

**מדדתי כל מילה מועמדת. זה מה שחוזר היום:**

| שאילתה | תוצאות | |
|---|---|---|

| `הסע` | 4 | ✅ |
| `הסעות` | 3 | ✅ |
| `מגורים` | 3 | ✅ |
| `חדרים` · `מרוהט` · `השכרה` · `קורס` | 2 | ✅ |
| `ציוד` · `כלי` · `פיגומים` | 1 | ✅ |
| **`דיור`** | **0** | 🔴 |
| **`קורסים`** | **0** | 🔴 |
| **`הסמכות`** | **0** | 🔴 |
| **`הסעה`** | **0** | 🔴 |
| **`מגורים לעובדים`** | **0** | 🔴 |
| **`ציוד וכלי עבודה`** | **0** | 🔴 |

## שלוש תקלות נפרדות, וכל אחת מוכחת בטבלה

**א. הקטגוריה לא נכללת בחיפוש.**
🔴 **`דיור` מחזיר אפס — והוא המילה שבשם הקטגוריה עצמה (`marketplace_categories.name_he = 'דיור להשכרה'`).** השאילתה נוגעת ב-`title`/`description`/`city` ולא ב-`category`.

**ב. אין שורש — והכיוון הפוך מהאינטואיציה.**
🔴 **`קורס`→2 אבל `קורסים`→0. `הסעות`→3 אבל `הסעה`→0.**
**הצורה שהמשתמש יקליד היא בדיוק זו שנופלת.**

**ג. הצירוף נבדק כמקשה אחת.**
🔴 **`מגורים`→3, `מגורים לעובדים`→0.** **התיבה מזמינה ״אני צריך טייחים במרכז״ — ובשירותים הנלווים כל צירוף של שתי מילים מת.**

## Do

- 🔴 **הוסף ל-`OR` גם את שם הקטגוריה ואת תת-הקטגוריה** — `JOIN marketplace_categories` ו-`LIKE` על `name_he`. **זה לבדו מחזיר את `דיור`**
- 🔴 **פצל את השאילתה למילים ו-`AND` ביניהן**, כשכל מילה היא `OR` על כל השדות. **זה מחזיר את `מגורים לעובדים`**
- ⚠️ **התאמה לפי תחילית, לא מילה שלמה** — כך `קורסים` יגיע ל״קורס״. **הדרך הזולה: חתוך סיומות ריבוי עבריות נפוצות (`ים`/`ות`) כשהמילה ארוכה מ-4 אותיות, וחפש את הגזע.** ⚠️ **זו היוריסטיקה, לא מורפולוגיה — אל תמשוך ספרייה חדשה בשביל זה**
- **סנן מילות עצירה קצרות** (`של`, `עם`, `לי`) כדי ש-`AND` לא יאפס הכל
- ⚠️ **אל תיגע ב-rewriter של העובדים** (`query_rewriter.py`). **הוא עובד. §2 הוא על `_search_marketplace` בלבד**
- **הדבק את אותה טבלה של 12 המילים לפני ואחרי.** 🔴 **אחרי — אף שורה לא באפס**

# §4 · 🔴 הבאנר בדסקטופ — `aspect-ratio` ו-`max-height` נלחמים זה בזה

**Yulian, 22.09:** *״הבאנר שנוסף במחשב אמור להיות מלבני לאורך המסך, לא מה שיש עכשיו.״*

**מדדתי את מה שנחת ב-R27 §3:**

```
.sponsor-banner-creative   aspect-ratio: 1037 / 609
                           max-height:   200px
                           max-width:    768px   (max-w-3xl)
                           → נמדד בפועל:  340 × 200
                           בתוך שורה של:  1120 רוחב
```

> 🔴 **`aspect-ratio` מנצח.** **הגובה נחתך ל-200, היחס גורר את הרוחב אחריו ל-340, והבאנר הפך לאריח קטן שצף במרכז שורה של 1120.**
> **תקרת הגובה לא הקטינה את הגובה — היא הקטינה את *כל הבאנר*.**

## ⚠️ ויש כאן בעיה שאי אפשר לפתור ב-CSS

**הקריאייטיב שעלה הוא `1037×609` — יחס 1.70:1.** ⚠️ **ולא `1200×628` ש-R20 §3 קבע. המפרט לא נאכף בהעלאה.**

**מלבן ארוך לרוחב המסך הוא יחס של בערך 8:1. קריאייטיב של 1.70:1 בתוך רצועה כזו:**

- **עם `contain`** → התמונה מצטמצמת למרכז ומשני צדדיה לבן ריק. **זה בדיוק מה שרואים עכשיו**
- **עם `cover`** → 🔴 **אסור.** **R20 §3a: חיתוך = הגילוי הנאות של מפרסם פיננסי הולך לאיבוד**

🔴 **המסקנה: אין CSS שהופך 1.70:1 לרצועה. צריך קריאייטיב שני.**

## Do

- 🔴 **הסר את `aspect-ratio` מסלוט הדסקטופ.** **הוא הגורם הישיר ל-340px**
- **הסלוט = רצועה בגובה קבוע:** `width: 100%` · `height: 130px` · `max-width` **זהה לרוחב התוכן של העמוד (`max-w-6xl`), לא `max-w-3xl`**
- 🔴 **`object-fit: contain` נשאר. לעולם לא `cover`**
- ⚠️ **ועד שיהיה קריאייטיב רצועה — מלא את צדי הרצועה בצבע רקע אחיד** כדי שהיא תיקרא כפס מכוון לרוחב ולא כאריח צף. **הצע `bg-slate-50` או שדה צבע לכל מפרסם. סמן `לאישור Yulian`**
