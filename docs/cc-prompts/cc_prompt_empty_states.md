# CC prompt — קבלן טרי מציג שגיאות במקום empty-state (אשכול)

## ממצא מאומת (Claude, מ-screens-export טרי, חשבון seed "קב" בלי מנוי/דאטה)
ארבעה מסכי קבלן מציגים **שגיאה אדומה** במקום מצב-ריק נקי:
- **דשבורד** — וידג'ט "המנוי שלך" → "קרתה תקלה, נסה שוב"
- **billing** — "המנוי שלך —" + באנר "קרתה תקלה, נסה שוב"
- **contractor/tenders** — "לא ניתן לטעון את הבקשות"
- **marketplace** — "תקלה בטעינת המודעות"

זה **QA-5 מוכלל**: endpoints שיכולים להיות ריקים לגיטימית (אין מנוי / אין בקשות / אין מודעות דיור) מטופלים כשגיאה. פוגע **בכל קבלן שזה עתה נרשם**, לא רק ב-seed.

## ⭐ STANDING RULE
`git tag pre-empty-states` לפני. staging + מובייל 390 + דסקטופ. דווח per-endpoint: 5xx אמיתי או empty-שמטופל-כשגיאה.

## Do
1. **אבחן כל אחד מ-4 ה-endpoints** לחשבון קבלן טרי (בלי מנוי/דאטה): מחזיר **5xx אמיתי**, או **200-ריק/404** שה-FE ממפה בטעות לשגיאה? הדפס status+payload לכל אחד.
2. **תקן לפי הסיבה:**
   - אם ה-endpoint 500 על "אין דאטה/אין מנוי" → תקן בשרת שיחזיר 200 ריק (או 404 סמנטי) במקום להתרסק.
   - אם ה-FE ממפה ריק/404 לשגיאה → הצג **empty-state** עם CTA:
     - מנוי: "אין מנוי פעיל" + "רכשו מנוי" (לא מקף, לא אדום).
     - tenders: "עדיין אין בקשות" + "בקשה חדשה".
     - marketplace: "עדיין אין מודעות" (או "אין מודעות דיור/ציוד") — ולוודא שמודעות הדיור מה-seed בכלל ציבוריות (אותה משפחה שתיקנו למודעות עובד; ייתכן שהדיור לא נחשף).
   - **שמור אדום רק לכשל אמיתי (5xx לא-צפוי).**
3. **עקביות:** אותו דפוס empty-state בכל המסכים (אייקון + משפט + CTA), לפי ה-DS.
