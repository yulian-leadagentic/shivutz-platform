# שלב 2 · התיקון (רק אחרי אישור)

## 2.1 · שדה נרדפות בכל שלוש הטבלאות

```sql
ALTER TABLE profession_types ADD COLUMN synonyms_he JSON NULL;
-- ואותו דבר לטבלאות המוצא והאזור, בשמותיהן בפועל
```

**JSON ולא טקסט מופרד בפסיקים** — כדי שלא נצטרך לפרסר, ושהאדמין יוכל לערוך כרשימה.

## 2.2 · מילוי — זה הלב, ואל תמציא

מלא לכל מקצוע קיים את הצורות שקבלן באמת מקליד. הכלל: **צורת בעל המקצוע, לא רק שם המקצוע**, ביחיד וברבים.

| `name_he` | `synonyms_he` — לפחות |
|---|---|
| ריצוף | `רצף · רצפים · ריצופים · פועל ריצוף · מרצף · **קרמיקה · אריחים · שיש · פרקט**` |
| חשמל | `חשמלאי · חשמלאים · חשמלאות` |
| גבס | `גבסן · גבסנים · עבודות גבס` |
| טיח | `טייח · טייחים · טיוח` |
| ברזל | `ברזלן · ברזלנים · ברזלנות · זיון` |
| אינסטלציה | `אינסטלטור · אינסטלטורים · שרברב · שרברבים · צנרת` |

> ⚠️ **הטבלה הזאת היא דוגמה, לא רשימה מלאה.** מלא את **כל** המקצועות שקיימים ב-DB בפועל.
> **אם אתה לא בטוח בצורה — אל תמציא. סמן אותה ברשימה נפרדת בדוח, ו-Yulian יכריע.** מילה נרדפת שגויה גרועה יותר מחסרה: היא תתפוס שאילתות שלא שייכות.

**למוצאים:** גם צורת התואר וגם צורת המדינה — `סין · סיני · סינים · סינית`, `אוקראינה · אוקראיני · אוקראינים`, `רומניה · רומני · רומנים`, `מולדובה · מולדובי · מולדובים`.

## 2.3 · הרשימות נטענות מה-DB, לא מהקוד

`PROFESSION_KEYWORDS` / `ORIGIN_KEYWORDS` / `REGION_KEYWORDS` נבנות **בזמן ריצה** מהטבלאות — `name_he` + כל ה-`synonyms_he` → אותו `code`.

- **cache של 60 שניות**, לא לשאול את ה-DB בכל שאילתה
- **אם ה-DB לא זמין — ליפול לרשימה הקשיחה הקיימת, לא לרשימה ריקה.** רשימה ריקה = כל חיפוש מחזיר את כל הקטלוג. השאר את הקבוע בקוד כ-fallback, אל תמחק אותו

## 2.4 · ה-system prompt נבנה דינמית

רשימת הקודים המותרים שמוזרקת ל-Haiku מגיעה מאותו מקור. **אסור שתישאר רשימה מילולית שנייה בקוד** — שתי רשימות שמתפצלות זה הבאג הבא.

# שלב 3 · המסך חייב להודות כשלא זוהה מקצוע

**גם אחרי התיקון, יישארו שאילתות שלא יזוהה בהן מקצוע.** היום המסך מציג במקרה כזה את כל הקטלוג **בלי לומר מילה** — הקבלן חושב ש-7 המודעות הן תשובה לשאלה שלו.

**Do:** כאשר `filters.profession_code` ריק **אבל הוחזרו תוצאות**, להציג מעל הרשימה:

```
לא זיהינו מקצוע מסוים — מציג את כל ההיצע, לפי סדר התאמה
```

- **"לפי סדר התאמה" נכון עובדתית** — ה-reranker באמת מסדר לפי רלוונטיות. אל תשנה את הנוסח לטענה שאינה נכונה
- אותו כלל ל-`aria-live`
- **רק כשיש תוצאות.** אפס תוצאות זה מסלול קיים (NM) — אל תיגע בו
- שינוי תצוגה בלבד. **אל תשנה את הפילטרים ואל תסנן בצד הלקוח**

לכל שורה: **גם ב-`mode=real` וגם ב-`LLM_REWRITER_FAKE_MODE=1`.** הערך של התיקון הזה הוא בדיוק בנפילה-לאחור, ולכן `fake` הוא הבדיקה החשובה.
