## 🔴🔴 חוסם השקה #1 · `MASTER_OTP=999999` פעיל בפרודקשן

**נמדד:** `railway variables --service auth --environment production`
מחזיר `MASTER_OTP`, והערך **זהה לזה של סטייג׳ינג — `999999`**.

**מה זה אומר:** [`services/auth/src/otp.js:141`](../../services/auth/src/otp.js)

```js
const masterCode = process.env.MASTER_OTP;
const isMasterCode = !!masterCode && code === masterCode;
const match = isMasterCode || await bcrypt.compare(code, otp.code);
```

כל אחד שמבקש OTP לכל מספר טלפון רשום בפרודקשן ומקליד `999999`
מקבל JWT אמיתי. זו עקיפת אימות מלאה.

**והקומנט בקוד מתאר בדיוק את החור הזה:**

> *"Previously defaulted to `'999999'`, which meant production accepted
> that code with no env-var ever set."*

התיקון נעשה. ואז המשתנה הוגדר ידנית בפרודקשן והחזיר את החור.

**`CLAUDE.md` אומר במפורש:** *"`MASTER_OTP=999999` is local + staging
only. **Production has it removed.**"* — זה לא נכון היום.

**מה שמצמצם (ולא מבטל):** `COMING_SOON_MODE=1` בפרודקשן, והמסך אכן
חוסם — אומת, ראה §3 למטה. **אבל ה-middleware לא חוסם `/api/*`
באופן מפורש** ([`middleware.ts:79`](../../services/frontend/src/middleware.ts)),
ושער הפרודקשן עונה לבקשות מהאינטרנט. מסך ה״בקרוב״ הוא לא גבול אבטחה
עבור ה-API.

**פעולה:** למחוק את `MASTER_OTP` משירות `auth` בפרודקשן. **רק Yulian.**

### ממצא נלווה · המצב הריק שולח להתחברות ולעולם לא להרשמה

הרגע עם הכוונה הגבוהה ביותר במשפך — מישהו חיפש ולא קיבל כלום —
מציג *התחבר כדי לראות מודעות עובדים ודיור* עם קישור יחיד ל-
`/login?returnTo=…`. ב-`/login` יש חמישה אלמנטים אינטראקטיביים בלבד
ואף אחד מהם אינו הרשמה.

**זה לא מבוי סתום מוחלט** — `login/page.tsx:317` מנתב טלפון לא רשום
שעבר OTP ל-`/register/<role>`. אבל הניתוב תלוי ב-`intent`, והקישור
מהמצב הריק לא נושא `intent`, אז הנפילה האחורית מחזירה את המשתמש
ל-`/`. ומעבר לזה, אין שום רמז חזותי שהקלדת טלפון בטופס *כניסה*
תיצור חשבון.

**לא תיקנתי** — זה נוגע בניתוב אימות, וזו החלטה שלך. ההמלצה: להוסיף
הרשמה למצב הריק ול-`/login`, ולהעביר `intent` בקישור.
