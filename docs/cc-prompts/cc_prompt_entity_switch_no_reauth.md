# CC prompt — החלפת ישות קיימת בלי אימות מחדש (P0 UX)

## הבאג (דווח ע"י בעל המוצר)
משתמש **מחובר כקבלן** רוצה לעבור לחשבון **התאגיד** שלו (ישות שהוא **כבר חבר בה** — מופיעה ב-`/select-entity`). במקום מעבר מיידי, המערכת מגלגלת אותו שוב דרך **טלפון + OTP מהתחלה**. זה מיותר: אימות מחדש נדרש רק להוספת ישות חדשה, לא למעבר בין חברויות קיימות.

**העיקרון:** מעבר בין ישויות שהמשתמש כבר חבר בהן = **re-prime של ה-JWT/session בלבד**, אפס טלפון/OTP. בדיוק כמו הנתיב ש-`/select-entity` כבר משתמש בו.

---

## ⭐ STANDING RULE
Mobile-first RTL, 390px + דסקטופ. `git tag pre-entity-switch` לפני. דווח before/after + הקובץ/שורה של ה-fix.

---

## Do
1. **אתר את מחליף-הישויות** ב-TopBar (ה-chevron/dropdown ליד האווטאר, שמראה "קבלן · <שם>"). מצא את ה-onClick של פעולת ההחלפה והדפס את הנתיב הנוכחי שהיא מפעילה.
2. **שורש הבעיה:** ההחלפה כנראה מפילה session / מנתבת ל-`/login` או ל-`/register` במקום לקרוא לנתיב ה-prime. אשר מה קורה בפועל (הדפס).
3. **התיקון — השתמש באותו prime-path של `/select-entity`:** בחירת ישות קיימת מהמחליף → קריאה לאותו endpoint שמזריק `entity_type`/`entity_id` ל-JWT/cookie → ניווט ל-dashboard של אותה ישות. **בלי `/login`, בלי `/auth/send-otp`, בלי OTP.**
4. **מקור אמת אחד לרשימת החברויות:** המחליף חייב להציג את *כל* החברויות של המשתמש (כמו `/select-entity`) — קבלן/תאגיד/מנהל — ולסמן את הפעילה. אם הרשימה מגיעה ממקום אחר מ-`/select-entity`, אחד את המקור.
5. **גבול ברור — לא לבלבל עם add-role:** אם המשתמש **אינו** חבר בישות מסוימת, הכניסה "הוסף חשבון קבלן/תאגיד" מובילה ל-`/register/<role>?add=1` (FU-1, נפרד). אבל לישות **קיימת** — לעולם לא רישום/OTP.
6. אחרי ההחלפה, ודא שה-RoleGuard/session קורא את ה-entity החדש נכון (בלי לולאת login, בלי מסך לבן).

## Acceptance

- [ ] הפוך: מתאגיד → קבלן, גם מיידי.
- [ ] המחליף מציג את כל 3 החברויות (קבלן/תאגיד/מנהל), הפעילה מסומנת.
- [ ] אין לולאת login ואין מסך לבן אחרי ההחלפה.
- [ ] עובד ב-390px + דסקטופ (יעד מגע ≥44px לפריטי המחליף).
- [ ] ישות שהמשתמש *לא* חבר בה → "הוסף חשבון" → `/register/<role>?add=1` (לא נשבר).

## Guardrails
`git tag pre-entity-switch`; להשתמש מחדש בנתיב ה-prime הקיים של `/select-entity` (לא להמציא חדש); **לא לגעת ב-OTP crypto / auth verify**; ניתוב מרוכז במקום אחד; production (main) לא נגעת — staging עד אישור מפורש. דווח את הקובץ/שורה של ה-onClick שתוקן ואת שם ה-prime endpoint שנעשה בו שימוש.
