# §1 · Backend — `GET /ads/public/{ad_id}`

`services/user-org/app/routes/ads.py`

## Do

```
GET /ads/public/{ad_id}
```

- **ללא אימות.** אותה רמת גישה כמו `/public/recent`
- מחזיר **בדיוק את הצורה של `AdSearchResult`** — כלומר `_serialize` **פחות** `owner_entity_type`, `active`, `view_count`, `created_at`, `updated_at`, `deleted_at`. אל תמציא צורה שלישית
- `active = TRUE AND deleted_at IS NULL` **בלבד**. מודעה שנמחקה או כובתה → **404**
- 404 מחזיר קוד יציב: `{"error": "ad_not_found"}`

## 🔴 שתי מלכודות

> **1 · סדר הנתיבים ב-FastAPI.** `@router.get("/{ad_id}")` בשורה 446 **תופס `/public/xxx` אם הוא מוגדר אחריו.** ודא שהנתיב החדש מוגדר **לפני** ה-catch-all, ליד שאר ה-`/public/*`. **בדוק בפועל שהוא לא מוחזר עם 403 של `_require_corp`** — זה הסימן שהנתיב נבלע.
>
> **2 · אסור שידלוף מידע קשר.** ה-endpoint הזה ציבורי. **טלפון, מייל ושם התאגיד יוצאים רק דרך `/contact-reveal`** שיש בו מכסות וחיוב. **הרץ `grep` על התשובה בפועל** ואמת שאין `phone`, `email`, `company_name`. אם `_serialize` מחזיר אותם — **עצור ודווח**, אל תשנה את `_serialize` המשותף.

# §2 · Frontend — לשמר את החיפוש

## 2.1 · `returnHref` נושא את השאילתה

`RevealModal.tsx:22`

```js
function returnHref(adId: string): string {
  return `/?reveal=${encodeURIComponent(adId)}`;     // ← אובד ההקשר
}
```

**Do:** צרף את השאילתה הפעילה — `/?q=<query>&reveal=<id>`.

- ה-query מגיע מה-state של דף החיפוש. **העבר אותו כ-prop ל-`RevealModal`** במקום לקרוא ל-`window.location` בתוך הרכיב
- **תקן גם את `returnTo.ts:157`** — `resolveDestination` בונה את אותה כתובת בנפילה מ-`pendingReveal`, ואם רק אחד מהשניים יתוקן הבאג ישרוד באחד המסלולים
- ⚠️ **`sanitizeReturnTo` חייב עדיין לאשר את הכתובת.** אל תרחיב את ה-whitelist שלו כדי לדחוף פרמטר — ודא שהוא מקבל `?q=` בנתיב יחסי. **אם הוא חוסם — דווח, אל תרופף בדיקת open-redirect.**

## 2.2 · הדף מריץ מחדש את החיפוש מ-`?q=`

בטעינה, אם יש `?q=` — מלא את תיבת החיפוש **והרץ את החיפוש**. המשתמש חוזר למסך שממנו יצא, לא לדף ריק.

## 2.3 · שליפה לפי `id` כשהמודעה לא בזיכרון

`page.tsx:723-725` — במקום להיכנע כשהיא לא נמצאת:

```
resp.results  →  resp.near_matches  →  recent  →  🆕 GET /ads/public/{id}
```

- רק אז, אם ה-API החזיר **404** — זו באמת מודעה שלא קיימת
- **בזמן השליפה — מצב טעינה.** לא שגיאה, ולא שקט

## 2.4 · ההודעה תיאמר את האמת

`page.tsx:744` — `'המודעה כבר לא זמינה'` נשארת **רק** אחרי 404 אמיתי מהשרת.

| מצב | הודעה |
|---|---|
| 404 מהשרת | `המודעה כבר לא זמינה` — ✅ נכון |
| שגיאת רשת / 5xx | `לא הצלחנו לטעון את המודעה. נסה שוב` **+ כפתור נסה שוב** |
| עדיין בטעינה | **בלי הודעה.** ספינר |

# §4 · הנקודתיים המיותרות ליד אייקון הטלפון — תו אחד

## הדיווח

> Yulian: *"יש נקודותיים מיותרים ליד האייקון של הטלפון."* (צילום מ-390, מודעה שנחשפה)

## Root cause — מאומת בקוד

```tsx
// app/page.tsx:1833 — תא הפעולה
<div className="results-cell" data-l="">
```
```css
/* app/globals.css:765 */
.results-cell[data-l]:not(:first-child)::before {
  content: attr(data-l) ": ";
}
```

**`[data-l]` מתאים גם כשהערך מחרוזת ריקה.** ה-`::before` מרנדר `"" + ": "` → **נקודתיים בודדות לפני האייקון.**

## Do — תקן את שניהם

```tsx
<div className="results-cell">                          {/* בלי data-l */}
```
```css
.results-cell[data-l]:not([data-l=""]):not(:first-child)::before {
```

> **למה שניהם ולא רק אחד:** הסרת התכונה מתקנת את המקרה הזה; חיזוק הסלקטור מונע מהבאג לחזור בפעם הבאה שמישהו יכתוב `data-l={someLabel}` ו-`someLabel` יהיה `undefined` או ריק. **תו אחד היום, שעה של דיבוג בעוד חודש.**

- **`grep -rn 'data-l=""' app/`** — ודא שאין עוד מופעים. דווח
- ⚠️ **אל תיגע ב-`:not(:first-child)`** — הוא קיים כדי שעמודת "מודעה" לא תקבל תווית. הוא נכון
