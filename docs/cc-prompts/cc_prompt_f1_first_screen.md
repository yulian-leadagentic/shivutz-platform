# §1 · ארבעת הכרטיסים → צ'יפים שמריצים חיפוש

## המצב היום

`services/frontend/src/app/page.tsx:97–102`:

```js
const CATEGORIES = [
  { key: 'workers',  label: 'עובדים לזמינות מיידית', scrollTo: 'search' },
  { key: 'housing',  label: 'דיור לפועלים',   scrollTo: 'search', prefill: 'מחפש מקום לינה' },
  { key: 'import',   label: 'ייבוא עובדים מחו״ל',  href: '/contractor/tenders' },
  { key: 'services', label: 'ציוד ושירותים (בקרוב)', soon: true },
];
```

**שלוש בעיות:**

1. **הם מלמדים ללחוץ, כשהמוצר מבקש לדבר.** כרטיס קטגוריה אומר "בחר קופסה"; המסך סותר את עצמו, והמשתמש בוחר את ההרגל שהוא מכיר
2. **`prefill: 'מחפש מקום לינה'` הוא שאילתה קטועה** — בלי כמות, בלי עיר. היא ממלאת את התיבה ומשאירה את המשתמש באמצע משפט
3. **`(בקרוב)` הוא עלות נטו** מעל הקפל ב-390

## Do

**מחק את `services`.** יחזור עם מסלול ספקי השירות.

**המר את שלושת הנותרים לשאילתות מלאות שרצות.** הצע ניסוח ב-PR; נקודת המוצא:

| במקום | שאילתה |
|---|---|
| `עובדים לזמינות מיידית` | `4 רצפים סינים לצפון` |
| `דיור לפועלים` | `דיור ל-20 פועלים בחיפה` |
| `ייבוא עובדים מחו״ל` | **נשאר קישור** ל-`/contractor/tenders` — הוא באמת ניווט, לא חיפוש |

> 🔴 **אף צ'יפ לא נכנס לפני שאומת שהוא מחזיר > 0 תוצאות בסטייג'ינג.**
> **הרץ כל אחד ודווח את מספר התוצאות בטבלה.** צ'יפ מובנה שמחזיר ריק הוא הרושם הראשון הגרוע ביותר שקיים.
> אם `דיור ל-20 פועלים בחיפה` מחזיר 0 — **נסה עיר אחרת ודווח**, אל תשאיר אותו.

# §2 · השאילתה מוקלדת לתוך התיבה

## המצב היום

`page.tsx:617` — `onClick={() => { setQ(ex); runSearch(ex); }}`.
הטקסט **קופץ** לתיבה והחיפוש רץ. המשתמש רואה תוצאות ולא הבין מאיפה.

## Do

הטקסט מופיע **תו-אחר-תו**, ורק אז החיפוש נשלח:

```
לחיצה
 ↓ 0ms       focus לתיבה
 ↓ 0–320ms   הקלדה תו-אחר-תו (RTL)
 ↓ 320ms     runSearch()
 ↓           skeleton + גלילה לתוצאות (קיים — SR-1/SR-4)
```

**זו לא קישוט — זה כל השיעור.** המשתמש רואה משפט שלם בעברית נכנס לתיבה ומחזיר תוצאות. **בפעם הבאה הוא יקליד בעצמו.**

## 🔴 שלוש דרישות מחייבות

1. **דילוג לסוף** — כל הקלדה, לחיצה על התיבה או Enter **מקפיצים מיד לטקסט המלא ומריצים.** ההקלדה **לעולם** לא מעכבת משתמש שיודע מה הוא רוצה
2. **`prefers-reduced-motion`** — הטקסט מופיע מיידית, בלי אנימציה. האתר כבר מכבד את זה; **אל תשבור**
3. **לחיצה על צ'יפ אחר באמצע הקלדה** — מבטלת את הקודמת ומתחילה מחדש. **בלי שתי הקלדות במקביל**

> **WCAG 2.2.2:** זו **אנימציה חד-פעמית בתגובה ללחיצה**, ולכן אינה "moving content" שדורש מנגנון עצירה.
> **אל תהפוך אותה ללולאה ואל תוסיף placeholder מתחלף** — שם היא כן נכנסת לתקן, וזה מחוץ לגל הזה.

# §3 · רצועת "המנוע הבין" → תגים

## המצב היום

`page.tsx:802` — שורת טקסט רציף:
```
המנוע הבין: עובדים · מקצוע: ריצוף · מוצא: סין (3 תוצאות)
```

**זה הרגע היחיד שבו רואים ש-AI עשה משהו**, והוא נראה כמו כיתוב.

## Do

**כל ממד הופך לתג ויזואלי:**

```
הבנתי:  [עובדים ✕]  [ריצוף ✕]  [סין ✕]  [4 ✕]  [צפון ✕]
```

- הטקסט מ-`labelFor(...)` — **בלי לגעת בלוגיקת המיפוי**
- **`✕` מסיר את התג ומריץ את החיפוש מחדש בלעדיו.** (זה גם L2 מהבקלוג, ומגיע כאן טבעי)
- **ממד שלא הובן לא מוצג בכלל** — אל תרנדר `כמות: —`. היעדר תג הוא המידע
- ספירת התוצאות נשארת כפי שהיא (NMC תיקן אותה — **אל תיגע**)

## §3b · 🔴 המסך חייב להודות כשלא זוהה מקצוע

**מקרה מאומת:** `קרמיקה` החזירה **7 תוצאות** — כל הקטלוג, כולל רתכים וטייחים — כי `profession_code` לא חולץ. הרצועה הציגה `עובדים` בלבד, **ומתחת ישבו 7 מודעות בלי שום אמירה שלא הופעל סינון.**

**Do:** כש-`filters.profession_code` ריק **ויש תוצאות**, מעל הרשימה:

```
לא זיהינו מקצוע מסוים — מציג את כל ההיצע, לפי סדר התאמה
```

- **"לפי סדר התאמה" נכון עובדתית** — ה-reranker באמת מסדר לפי רלוונטיות (ב-`קרמיקה` הוא דחף את שלוש מודעות הריצוף למקומות 1–3). **אל תשנה לנוסח שאינו נכון**
- אותו נוסח ל-`aria-live`
- **רק כשיש תוצאות.** אפס תוצאות זה מסלול NM קיים — **אל תיגע בו**

> אם `cc_prompt_synonyms.md` כבר רץ וסגר את `קרמיקה` — **§3b עדיין נדרש.** תמיד יישארו שאילתות בלי מקצוע מזוהה.

# §4 · "איך זה עובד" — נוסח חדש ומיקום חדש

## הבעיה

```
1 · הרשמה ואימות  →  2 · חיפוש והתאמה  →  3 · סגירת עסקה
```

**זה מתאר תהליך שאינו שלנו.** אצלנו **מחפשים בלי להירשם**; ההרשמה נדרשת רק ב-reveal. הסעיף מציב מחסום שלא קיים, ומציב אותו בשלב 1 — לפני שהמבקר קיבל ערך כלשהו.

## Do

**אתר את הרכיב** (`grep -rn "איך זה עובד"`), והחלף ל:

```
1 · שואלים בעברית          בלי הרשמה · בכתב או בדיבור
2 · המערכת מבינה ומציגה     מקצוע · מוצא · אזור · כמות
3 · מתחברים וחושפים קשר     ופונים ישירות לתאגיד
```

**שלב 3 הוא המקום היחיד שבו מופיעה הרשמה** — וזה נכון עובדתית.

**וגם:**
- **הסעיף יורד מתחת לאזור התוצאות.** מי שלחץ צ'יפ לא צריך אותו
- **צבע אחד לשלוש המסגרות.** היום ירוק/נייבי/כתום — נקרא כשרירותי. המספר הוא ההיררכיה
- הבאנר `הכל במקום אחד` — **נשאר. אל תיגע**
