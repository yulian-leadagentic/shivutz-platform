# CC prompt — Seed data לסטייג'ינג (דרך שכבת השירות, אידמפוטנטי)

## מטרה
לזרוע דאטת בדיקה **ריאליסטית בעברית** בסטייג'ינג: קבלנים, תאגידים, מודעות עובדים, מודעות דיור — עם **מגוון מצבי מנוי ומכסות חשיפה**. נפח **בינוני**. **בלי tenders** (קיים כבר).

## עקרונות-על (חובה)
1. **דרך שכבת השירות / API — לא INSERT גולמי.** הדאטה חוצת-שירותים (auth user → user-org membership → entity → ad → subscription). זרע דרך פונקציות ה-create הקיימות של השירותים או דרך ה-endpoints, כדי לשמור אינווריאנטים ולשרוד migrations. השתמש ב-**MASTER_OTP `999999`** לכל login/רישום (אפס SMS).
2. **אידמפוטנטי.** upsert לפי מפתח טבעי (טלפון / ח.פ). הרצה חוזרת לא משכפלת.
3. **guard לסטייג'ינג בלבד.** הסקריפט מסרב לרוץ אם `NODE_ENV`/env אינו staging, או אם ה-DB host אינו של staging. הדפס אזהרה וצא עם קוד שגיאה. **לעולם לא production.**
4. **סימון + reset נקי.** כל שורה זרועה נושאת סימון (דגל `is_seed=true` אם יש עמודה, אחרת טווח טלפונים שמור — למשל `0525xxxxxx` בלוק ייעודי + prefix ח.פ מזוהה). `npm run seed:reset` מוחק **רק** שורות מסומנות. אף פעם לא נוגע בדאטה אמיתית או בחשבון `0525278625`.
5. **דטרמיניסטי.** קטלוג נתונים קבוע בקובץ fixture (JSON/TS) — לא random בכל ריצה. QA משוחזר. אם משתמשים ב-faker → seed קבוע.

## מבנה
- `tools/seed/` : `seed.mjs` (מריץ), `catalog.*` (הנתונים), `reset.mjs`.
- `package.json`: `seed:staging`, `seed:reset`.
- קרא env/credentials מאותו מקום שהשירותים קוראים; אל תצמיד סודות בקוד.

## מה לזרוע (נפח בינוני)

### קבלנים (~15)
שמות עבריים אמיתיים; אזורים אמיתיים (צפון/מרכז/דרום/ירושלים/שרון). מצבים מעורבים:
- ~5 **kablan מאומת** (`kablan_verified_at` set), ~5 **לא מאומת** (pending), ~5 חדשים.
- מנוי: חלק **trial** (בתוך התקופה), חלק **פעיל** (tier_1/2/3), חלק **פג/paused**.
- **מכסת חשיפות מנוצלת חלקית** לחלק (למשל 3/10, 25/40) — לבדיקת מד-מכסה ו-paywall.
- לפחות אחד **רב-ישויות** (קבלן+תאגיד על אותו user) לבדיקת החלפה.

### תאגידים (~10)
שמות חברות עבריים + ח.פ מזוהה-מזויף. מצבים:
- חלק **מאומת מול רשם** (gov-list match), חלק **pending**.
- tier_1/2/3 מעורב; חלק trial, חלק פעיל, אחד פג.

### מודעות עובדים (~50)
מפוזרות על התאגידים. שדות מה-enums האמיתיים:
- מקצועות: ריצוף, אינסטלציה, ברזלנות, טיח, שלד, חשמל, גבס, ריתוך.
- לאומים: סין, אוקראינה, מולדובה, סרי לנקה, הודו, נפאל.
- אזורים אמיתיים; מספר עובדים משתנה.
- **מצבים מגוונים:** published, paused, **מקודמת (boost פעיל)**, פג-תוקף. לפחות 5–8 מקודמות (לבדיקת קרוסלת המקודמות והתגית "מקודם").

### מודעות דיור (~8–10)
אם משטח הדיור קיים (gradient ירוק): מיקומים, קיבולת, מחיר, כמה מקודמות. אם המשטח לא קיים בקוד — דלג ותעד.

### מצבי מנוי ומכסות (חתך רוחבי)
ודא שהסט מכסה: trial-בתחילתו · trial-לקראת-סיום · פעיל-עם-מכסה-מלאה · פעיל-עם-מכסה-כמעט-גמורה · פג-תוקף/paused. זו הפואנטה — לא רק כמות.

## Acceptance
- [ ] `npm run seed:staging` רץ נקי מול staging, מדפיס ספירות (קבלנים/תאגידים/מודעות עובדים/דיור שנוצרו/עודכנו).
- [ ] הרצה שנייה = **0 כפילויות** (idempotent upsert).
- [ ] הדאטה נראית ב-UI: רשימות מתמלאות, פילטרים עובדים, קרוסלת מקודמות מציגה boosts, מד-מכסה/paywall מגיב למכסה חלקית.
- [ ] `npm run seed:reset` מוחק רק שורות מסומנות; דאטה אמיתית ו-`0525278625` נשארים.
- [ ] guard: ניסיון הרצה מול non-staging נכשל בבירור.
- [ ] הנתונים בעברית תקינה, מקצועות/לאומים מה-enums (לא ערכים לא-חוקיים).

## Guardrails
`git tag pre-seed-tooling`; דרך שכבת השירות (לא SQL גולמי חוצה-שירותים); **staging בלבד** עם guard; **בלי tenders** (קיים); לא לשנות לוגיקה עסקית/סכימה — רק כלי seed; production (main) לא נגעת. דווח: קבצים שנוצרו, שיטת הסימון/reset, וספירות אחרי הרצה ראשונה + שנייה (להוכחת idempotency).
