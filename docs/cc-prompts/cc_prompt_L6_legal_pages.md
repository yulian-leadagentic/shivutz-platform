## 2.1 · תנאי שימוש — מה חייב להיכלל

| | |
|---|---|
| מיהו נותן השירות | **Lead Agentic** — השם המשפטי, לא TagidAI. ח.פ, כתובת |
| מהות השירות | **פלטפורמת תיווך מידע.** ⚠️ **הסעיף הקריטי:** אנחנו לא מעסיקים, לא מספקים עובדים, ולא צד לעסקה בין קבלן לתאגיד |
| כשירות | משתמש עסקי בלבד, מורשה לחייב את הארגון |
| מנויים | תקופת ניסיון · חידוש אוטומטי · **ביטול** · **מדיניות החזרים** |
| חשיפות | מכסה חודשית · **אינה נצברת** · חשיפה שנוצלה אינה מוחזרת |
| תוכן משתמשים | האחריות על המפרסם · זכות הסרה |
| הגבלת אחריות | אין אחריות לדיוק מודעות, לזמינות עובדים או לתוצאות העסקה |
| הפסקת שירות | מתי חשבון מושהה או נסגר |
| דין ושיפוט | דין ישראלי · סמכות בתי המשפט בישראל |

> 🔴 **"אנחנו לא צד לעסקה" הוא הסעיף שמגן על החברה.** תיווך עובדים זרים מפוקח בכבדות, ואי-בהירות כאן היא החשיפה הגדולה ביותר. **כתוב אותו במפורש, מוקדם במסמך, ובעברית פשוטה.**

## 2.2 · מדיניות פרטיות — לפי מה שהקוד באמת אוסף

**אל תכתוב תבנית גנרית. תאר את המערכת שלנו.**

**מה נאסף בפועל, מהקוד:**

| | |
|---|---|
| טלפון | OTP — `auth_db.users` |
| שם, אימייל, ח.פ | רישום |
| מסמכים | רישיונות ותעודות שהועלו |
| התאמה למרשם ממשלתי | `gov_corporations_registry` · `verification_tier` |
| **שאילתות חיפוש** | נשלחות ל-**Anthropic (Claude Haiku)** לפירוש |
| **הקלטות קול** | נשלחות ל-**ElevenLabs** לתמלול |
| רשומות חשיפה | `contact_reveals` — מי חשף את מי ומתי |
| תשלומים | **Cardcom.** ⚠️ **פרטי כרטיס לא נשמרים אצלנו — רק טוקן** |
| SMS/WhatsApp | Vonage |

**חייב לכלול:** מטרות ובסיס חוקי · **צדדים שלישיים בשמם המפורש** (רשימה למעלה) · תקופות שמירה · **זכות עיון, תיקון ומחיקה** · אבטחה · עוגיות · **פרטי קשר לפניות בנושא פרטיות**.

> 🔴 **שתי נקודות שמסמך תבנית תמיד מפספס וכאן הן מהותיות:**
> **אחת —** *"שאילתות החיפוש שלך נשלחות לספק AI חיצוני"*. זה מידע שהמשתמש הקליד, יוצא מהארץ. **חייב להיכתב.**
> **שתיים —** `contact_reveals` יוצר **רשומה של מי התעניין במי**. זה מידע עסקי רגיש על שני הצדדים. **חייב להיכתב, וגם למי הוא נחשף** — בפרט לאור PRD-1, שמציג לתאגיד נתונים על החשיפות.

## 2.3 · עוגיות
