## Root cause — אותר, אל תחפש מחדש

**חוליה אחת חסרה בשרשרת שכבר בנויה.**

מה שכבר עובד:
| קובץ | שורה | מה |
|---|---|---|
| `features/advertising/RevealModal.tsx` | 41 | `writePendingReveal({ adId, kind })` — הכוונה נשמרת ✓ |
| `app/page.tsx` | 358-366 | קורא `readPendingReveal()` ומקדם ל-`?reveal=<adId>` ✓ |
| `app/page.tsx` | 368+ | ה-effect שמבצע את החשיפה בפועל לפי `?reveal=` ✓ |
| `app/page.tsx` | 319 | `clearPendingReveal()` אחרי חשיפה מוצלחת ✓ |

**מה ששבור** — `app/login/page.tsx:58-62`:
```js
function redirectByRole(router, role) {
  if (role === 'admin')       { router.push('/admin/dashboard'); return; }
  if (role === 'corporation') { router.push('/corporation/dashboard'); return; }
  router.push('/contractor/dashboard');
}
```

**ניתוב ללא תנאי.** אין `next`, אין `returnTo`, אין בדיקת כוונה שמורה. נקרא ב-**177** וב-**284**. שורה **205** מקודדת דשבורדים בנפרד, ושורה **218** דוחפת ל-`/select-entity`.

**התוצאה:** אפקט ההצלה ב-`page.tsx:358` רץ **רק בעמוד הבית**. אחרי ההתחברות המשתמש ב-`/contractor/dashboard`, ה-effect לא נטען, והכוונה יושבת ב-storage בלי שאיש יקרא אותה.

> ההערה בקוד ב-`page.tsx:355` אומרת *"returnTo lost to refresh / OTP restart / tab close"* — כלומר תוכנן returnTo שמעולם לא נבנה בצד ההתחברות.

## Do

### 1. כוונה שמורה גוברת על ניתוב ברירת-מחדל 🔴 **הליבה**

ב-`app/login/page.tsx`, **לפני** כל ניתוב לדשבורד, בדוק כוונה שמורה:

```
אם readPendingReveal() מחזיר כוונה
  → router.push(`/?reveal=${pending.adId}`)
אחרת
  → הניתוב לפי תפקיד כמו היום
```

**השתמש ב-`readPendingReveal` הקיים** מ-`@/features/prospect/state`. **אל תמציא מנגנון חדש** — הוא כבר שורד רענון, restart של OTP, וסגירת טאב.

**החל את זה על כל נתיבי היציאה:**
- `redirectByRole` (נקרא ב-177 וב-284)
- הניתוב הישיר בשורה **205**
- הנתיב ל-`/select-entity` בשורה **218** — ראה סעיף 3

### 2. `?next=` כשכבה שנייה

הוסף תמיכה ב-`?next=<path>` בדף ההתחברות, וגרום למי שמנתב ל-`/login` להעביר אותו.

**סדר העדיפות:** `?next=` → כוונה שמורה → ניתוב לפי תפקיד.

> **אבטחה:** קבל **רק נתיבים יחסיים** שמתחילים ב-`/`. דחה `//`, `http://`, `https://` וכל דבר עם host. זו פרצת open-redirect קלאסית.

### 3. `/select-entity` באמצע הדרך

משתמש עם כמה ישויות עובר דרך `/select-entity` (שורה 218). **הכוונה חייבת לשרוד גם את זה** — אחרי בחירת ישות, אותה לוגיקה: כוונה שמורה קודמת לדשבורד.

### 4. גם בהרשמה

אותו תרחיש בדיוק דרך `/register`. **בדוק ותקן שם באותו אופן.** משתמש שנרשם מתוך כוונת חשיפה הוא הליד הכי חם שיש.

### 5. שהחשיפה באמת תקרה בנחיתה

אחרי החזרה ל-`/?reveal=<adId>`, ה-effect בשורה 368 מחפש את המודעה ב-`resp.results` **או** ב-`recent`:

```js
const ad = resp?.results.find((a) => a.id === target)
        ?? recent.find((a) => a.id === target);
if (!ad) return;  // ← ממתין בשקט
```

**אם המודעה לא באף אחד מהם — לא קורה כלום, בשקט.** המשתמש חוזר לעמוד הבית ולא מבין למה.

**תקן:** אם היעד לא נמצא אחרי שהטעינה הסתיימה — או לטעון את המודעה הבודדת לפי id, או להציג הודעה בעברית ("המודעה כבר לא זמינה") ולנקות את הכוונה. **לא כישלון שקט.**

### 6. ניקוי

`clearPendingReveal()` כבר נקרא בהצלחה (`page.tsx:319`) ובסגירה מפורשת (`RevealModal:45`). **ודא שהוא נקרא גם כשהכוונה מומשה או פגה**, כדי שלא תרדוף אחרי המשתמש בסשן הבא.
