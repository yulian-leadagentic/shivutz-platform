## 3b · שני פגמים ב-`mapApiError` שמצאתי בקריאה — **קיימים בלי קשר לשאלה איזה מהם זה**

`services/frontend/src/lib/api/errors.ts`

### פגם א׳ · `detail` של FastAPI הוא **מערך**, והקוד מתייחס אליו כאובייקט

```ts
// שורה 296
if (o.detail && typeof o.detail === 'object') {
  return { ...(o.detail as ApiErrorPayload), ...(o as ApiErrorPayload) };
}
```

**כל 422 של FastAPI מחזיר `detail: [{loc, msg, type}]`.** `typeof [] === 'object'` — **אז התנאי נתפס**, הפריסה נותנת `{0: {...}}`, ואין `message`, אין `error`, אין `code`. **כל שגיאת ולידציה במערכת מתקרסת להודעה הגנרית.**

**Do:** `Array.isArray(o.detail)` → **קח את `msg` של הפריט הראשון**, ואם יש `loc` — **ציין את שם השדה**. *"מספר טלפון נייד: ערך לא תקין"* עדיף פי כמה מ-"קרתה תקלה".

### פגם ב׳ · שלב 3 לא מגיע אף פעם עבור `Error`

```ts
// normalize, שורה 291
return { error: m };        // ← תמיד error, אף פעם לא message
...
// mapApiError, שורה 273
if (payload.message) return payload.message;   // ← לא יכול לרוץ במסלול הזה
```

**כשהודעת ה-`Error` אינה עברית ואינה קוד מוכר, היא נכנסת כ-`error`**, שלב 2 לא מוצא אותה בטבלה, **ושלב 3 מחפש `message` שלא קיים.** התוצאה תמיד `DEFAULT_MESSAGE`.

**Do:** ב-`normalize`, **החזר גם `message: m`** לצד `error: m`. שלב 2 עדיין מנצח כשיש קוד; שלב 3 סוף-סוף מקבל את הטקסט המקורי.

⚠️ **דווח אם התיקון הזה מתחיל להדליף אנגלית למסכים.** אם כן — **זה ממצא, לא רגרסיה: פירושו שיש קודים שהשרת מחזיר ולא נמצאים בטבלה.** רשום אותם.

# §5 · סריקת כל שדות הקלט + מילוי אוטומטי

> **Yulian:** *"תעבור על כל השדות שיש בטפסי הרישום או בכל שדה שמקלידים בו ערך ותוודא תקינות ותאימות למילוי אוטומטי של גוגל."*

## מה שכבר מצאתי ב-`components/ui/input.tsx` — **שלושה דברים**

### א׳ · 🔴 אין `name`, אין `autoComplete`. **בשום מקום**

**מילוי אוטומטי של Chrome מזהה שדות לפי `autocomplete` ולפי `name`.** בלי שניהם — **הוא פשוט לא ימלא.** זה לא באג עדין, זו התכונה שחסרה לגמרי.

**מפה מינימלית:**

| שדה | `autoComplete` |
|---|---|
| שם פרטי | `given-name` |
| שם משפחה | `family-name` |
| שם מלא | `name` |
| טלפון | `tel` |
| אימייל | `email` |
| חברה | `organization` |
| תפקיד | `organization-title` |
| עיר | `address-level2` |
| קוד OTP | `one-time-code` |

🔴 **`one-time-code` בשדה ה-OTP הוא ניצחון מיידי** — iOS ואנדרואיד מציעים את הקוד מה-SMS. **בפלטפורמה שכל כניסה בה היא OTP, זה משנה את חוויית ההתחברות.**

🔴 **ח.פ / ע.מ / מספר רישיון קבלן → `autoComplete="off"`.** **אין להם ערך אוטומטי נכון, ומילוי שגוי בשדה מזהה גרוע משדה ריק.**

### ב׳ · ⚠️ ה-`id` נגזר מתווית עברית

`input.tsx:12`

```ts
const inputId = id ?? label?.toLowerCase().replace(/\s+/g, '-');
```

**`"שם פרטי"` → `id="שם-פרטי"`.** **שתי תוויות זהות באותו דף → שני אלמנטים עם אותו `id`** — וה-`<label htmlFor>` מצביע על הראשון בלבד. **קורא מסך יקריא את התווית הלא נכונה, ולחיצה על התווית תמקד את השדה הלא נכון.**

**Do:** `React.useId()` כבסיס, והתווית רק כקידומת קריא. **בדוק שאין `id` כפול בטפסי ההרשמה — `document.querySelectorAll('[id]')` וספור.**

### ג׳ · ⚠️ בחירת כל הטקסט ב-focus

`input.tsx:17-26` בוחר את כל התוכן בכל focus. **זה נוסף בכוונה (QA-R3 #21).**
