# §1 · 🔴 `/admin/subscriptions` — `קרתה תקלה, נסה שוב עוד רגע`

## מה שמצאתי

`services/frontend/src/app/admin/subscriptions/page.tsx:46`

```tsx
setRows(await apiFetch<AdminSubRow[]>(`/admin/subscriptions?${params.toString()}`));
} catch (e) { setError((e as Error).message ?? ''); }
```

**ההודעה שבצילום היא התרגום העברי של `internal_error`.** כלומר **השרת החזיר 500**, לא רשימה ריקה.

⚠️ **ושים לב לסתירה בצילום:** ההודעה האדומה **וגם** `אין מנויים תואמים` מוצגות יחד. **הדף מרנדר "ריק" ו"שגיאה" בו-זמנית** — וזה מטעה: מנהל שיראה רק את החלק התחתון יסיק שאין מנויים במערכת. **תקן גם את זה: שגיאה ← אין מצב ריק.**

## 1a · אבחן. אל תנחש

**פתח את המסך, F12 → Network → `GET /admin/subscriptions`. דווח status, גוף מלא, והלוג של השירות שמגיש אותו.**

## 1b · שני חשודים שאני מהמר עליהם — בדוק אותם ראשונים

### א׳ · צירוף בין סכימות + התנגשות collation

`AdminSubRow` מכיל `entity_name`. **`subscriptions` יושבת ב-`payment_db`; `corporations` ו-`contractors` ב-`org_db`.** כדי להביא שם צריך צירוף חוצה־סכימות.

🔴 **וזו בדיוק הנקודה שכבר נשכה אותנו:** `ads.owner_entity_id` הוא `utf8mb4_0900_ai_ci` ו-`corporations.id` הוא `utf8mb4_unicode_ci`. **`search.py:314` נאלץ ב-`COLLATE utf8mb4_0900_ai_ci` מפורש.** **אם השאילתה כאן מצרפת בלי ההמרה — MySQL זורק `Illegal mix of collations`, שנראה כמו 500 גנרי.**

**בדוק את זה ראשון. זו בדיקה של דקה.**

### ב׳ · העמודות החדשות מ-L4

`071_subscription_plans_seats.sql` הוסיפה `included_users` ו-`extra_user_price_nis`. **אם השאילתה כאן מושכת `plan.*` או מצרפת ל-`subscription_plans`, ייתכן שהיא מפרשת שורה בצורה שהשתנתה.**

**ודא ש-`071` ו-`072` באמת רצו בסביבה הזו:**

```sql
SELECT * FROM auth_db._migrations WHERE name LIKE '07%' ORDER BY name;
```

🔴 **אם מיגרציה חסרה — זה לא באג קוד. דווח מיד ואל תתקן קוד.**

## 1c · ההודעה

**`(e as Error).message` — המסך הזה לא משתמש ב-`mapApiError`.** ⚠️ **U8 §3 מתקן את `mapApiError`. החלף כאן ל-`mapApiError`** כדי שהמסך יירש את התיקון.

# §2 · 🔴 רשימת התאגידים המורשים — הספירה נכונה, התוכן ריק

## מה שבצילום

```
שנים שנטענו במערכת:   450 שורות  ·  222 עם ח.פ תקין
תאגידים ברשימה הפעילה: 450 רשומות
כל שורה:               —   ·   —   ·   ללא ח.פ
```

> **450 שורות קיימות. 222 מהן עם ח.פ תקין. והרשימה מציגה מקפים ב-450 מתוך 450.**
> **זה לא "אין נתונים" — הספירה מוכיחה שיש. השורות מגיעות ללקוח ריקות.**

## 2a · האבחנה שמצמצמת את החיפוש

`services/frontend/src/app/admin/gov-corps-registry/page.tsx:218-231`

```tsx
interface RegistryRow {
  id: string;
  serial_no?:        number | null;
  business_number?:  string | null;
  company_name_he?:  string | null;
  address?:          string | null;
  …
}
```

🔴 **כל השדות אופציונליים.** כלומר **אם ה-API מחזיר שמות שדות אחרים, TypeScript לא יתלונן, והדף ירנדר `—` בשקט לנצח.** **זו הסיבה שהבאג הזה שרד.**

## 2b · Do

1. **תפוס את התשובה הגולמית של נתיב הרשימה. הדבק שורה אחת כמו שהיא**
2. **השווה שם-בשם מול `RegistryRow`.** חשודים: `company_name` מול `company_name_he` · `corp_number` / `hp` מול `business_number`
3. **אם השדות תואמים אבל ריקים — הבעיה ב-`SELECT` או ביבוא ה-PDF.** **בדוק ב-DB ישירות:**
   ```sql
   SELECT serial_no, business_number, company_name_he
     FROM gov_corporations_registry LIMIT 5;
   ```
   **הדבק. זה מכריע בין "היבוא לא שמר" ל"הקריאה לא מביאה"**
4. 🔴 **אחרי שזה עובד — הסר את ה-`?` מהשדות ש-API מתחייב להחזיר.** **טיפוס שמתיר הכל לא הגן על כלום**

⚠️ **אם היבוא הוא שלא שמר — אל תריץ יבוא מחדש בלי לדווח.** **טעינה מחליפה את כל הרשומות לאותה שנה** (כתוב בעמוד עצמו). **אם הנתונים בכל זאת שם, יבוא שגוי ימחק אותם.**

# §3 · רשימת המשתמשים — שורה מתרחבת

> **Yulian:** *"ברשימת משתמשים כל שורה צריכה להתרחב ולהציג את הפרטים של התאגיד ומי הבעלים ליצירת קשר, תוסיף גם ציון האם התאגיד במסגרת מנוי פעיל."*

**זו בקשה, לא באג.** `services/frontend/src/app/admin/users/page.tsx`

## מה להציג בהתרחבות

| | |
|---|---|
| **הישות** | שם · סוג · ח.פ · סטטוס אישור · תאריך הצטרפות |
| **הבעלים** | **שם, טלפון ואימייל של בעל החשבון** — לא של השורה שנלחצה. **זה העיקר בבקשה: מנהל שרואה משתמש רוצה לדעת למי להתקשר** |
| **המנוי** | **מסלול · סטטוס · תאריך חידוש · `X מתוך Y משתמשים`** |

## 3a · 🔴 המנוי — אותו צירוף חוצה־סכימות של §1

**אל תפתור אותו פעמיים.** **תקן את §1 קודם, ואז השתמש באותה שאילתה או באותו עוזר.**

## 3b · פרטים שקובעים אם זה שימושי

- **התרחבות בלחיצה**, לא ניווט. ⚠️ **הטבלה כבר משתמשת ב-`useTableState`** — **בדוק אם יש שם תמיכה בהתרחבות לפני שאתה כותב אחת**
- **טען את פרטי ההתרחבות בלחיצה, לא מראש.** **13 משתמשים היום, אבל צירוף מנויים לכל שורה בטעינה יהפוך את המסך לאיטי ברגע שיהיו 300**
- **מצב "אין מנוי" ≠ שגיאה.** *"אין מנוי פעיל"* — 🔴 **אותו כלל כמו U5 §3**
- **טלפון ואימייל — לחיצים** (`tel:` · `mailto:`). **זו כל הפואנטה של "ליצירת קשר"**
- **אם הישות נטענת ונכשלת — הצג שגיאה בשורה, לא ספינר נצחי.** **U5 §2 שוב**

# §4 · 🔴 עריכת ארץ מוצא → `country_not_found` — **ויש לזה תוצאה חמורה יותר**

## מה שבצילום

השורה `PH · פיליפינים · Philippines` במצב עריכה, ובראש הטבלה: **`country_not_found`**.

**ושתי שורות בצילום במצב `מושבת`: `PH` ו-`RO`.**

## 4a · ההשערה שלי, ולמה היא מטרידה

`adminApi.updateOrigin` שולח `PATCH /admin/enums/origins/{code}`.

**אם הנתיב מאתר את השורה עם סינון כמו `WHERE code=%s AND is_active=1` — ארץ מושבתת אינה נמצאת, והתוצאה היא בדיוק `country_not_found`.**

> 🔴 **וזו לא רק בעיית עריכה.**
> `origins/page.tsx:93` — כפתור **"הפעל"** קורא ל-`updateOrigin(code, { is_active: true })`.
> **כלומר אם ההשערה נכונה, ארץ שהושבתה לא ניתנת להפעלה מחדש. לעולם.**
> **`026_disable_philippines_origin.sql` השבית את הפיליפינים במיגרציה — ואם Yulian ירצה להחזיר אותן, אין לו דרך דרך הממשק.**

**דלת חד־כיוונית בממשק ניהול היא באג חמור יותר מהודעת שגיאה.**

## 4b · חשוד שני — מלכודת `rowcount`

**אותה מלכודת מ-U4 §2.** `cur.rowcount` ב-pymysql מחזיר שורות ש**השתנו**, לא ש**הותאמו**.

**עורך ארץ ושומר בלי לשנות ערך → 0 → הקוד מסיק "לא נמצאה".**

⚠️ **בצילום, שם הפיליפינים באנגלית נראה זהה לערך הקיים.** **ייתכן מאוד שזה המקרה הזה.**

## 4c · Do

1. **תפוס את התשובה. status + גוף + לוג. דווח לפני תיקון**
2. **אם זה סינון `is_active`** → **הסר אותו ממסלולי הניהול.** 🔴 **אדמין חייב לראות ולערוך גם ארצות מושבתות — זו כל מטרת המסך**
3. **אם זה `rowcount`** → **הפרד "לא נמצאה" מ"לא השתנתה", בדיוק כמו U4 §2:**
   ```
   SELECT קיים?  לא  →  404 country_not_found
   קיים + rowcount 0  →  200 עם השורה הנוכחית
   rowcount > 0       →  200
   ```
   🔴 **אל תוסיף `CLIENT.FOUND_ROWS` לחיבור.** אותו איסור כמו ב-U4
4. 🔴 **בדוק את המעגל המלא: השבת ארץ → הפעל אותה מחדש → ודא שהיא חזרה.** **זו הבדיקה שחושפת את הדלת החד־כיוונית**
5. **`country_not_found` → הוסף ל-`CODE_TO_HE`** ב-`services/frontend/src/lib/api/errors.ts`: **`'הארץ לא נמצאה ברשימה'`**
6. **המסך מציג `e.message` גולמי** (שורות 85, 97). **החלף ל-`mapApiError`**

## 4d · ⚠️ בדוק את השכנים

**אם הסינון הזה קיים בארצות — כנראה הוא קיים גם במקצועות ובאזורים.**

```bash
grep -rn "is_active" services/*/app/routes/*admin* services/*/src/routes/*admin*
```

**דווח כל מסלול ניהול שמסנן `is_active` בשליפה לפני עדכון.**
